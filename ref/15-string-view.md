## 30. `std::string_view`

### Зачем он: `const std::string&` не всегда бесплатен

Из [раздела 9](04-funkcii.md#три-способа-передать-аргумент) правило: строку в функцию передают как `const std::string&`, чтобы не копировать. Это верно — но есть тонкость. Если позвать такую функцию с **литералом**, копия всё-таки создаётся:

```cpp
void print(const std::string &s) { std::cout << s; }

print("привет");        // ⚠️ из "привет" тихо создаётся временный std::string (выделение памяти)
```

`std::string_view` (`<string_view>`) убирает и это: он принимает и `std::string`, и литерал, и кусок другой строки — **без единой копии**.

### Что это: окно в чужую строку

`string_view` не хранит символы. Внутри — всего лишь **указатель на начало и длина**: «смотри вот сюда, вот столько букв». Данные принадлежат кому-то другому; view только читает их.

```cpp
#include <iostream>
#include <string>
#include <string_view>

void greet(std::string_view name) {        // принимает что угодно строковое, без копии
  std::cout << "Привет, " << name << "!\n";
}

int main() {
  std::string user = "Аня";
  greet(user);            // из std::string — без копии
  greet("Борис");         // из литерала — без создания временной строки
  return 0;
}
```

Поэтому `string_view` — почти идеальный **тип параметра** для функций, которые строку только читают: одна подпись работает со всеми источниками текста и ничего не копирует.

### Что с ним можно делать

Всё, что не меняет строку и не требует владения ею:

```cpp
std::string_view s = "hello.txt";

std::cout << s.size() << "\n";           // → 9
std::cout << s[0] << "\n";               // → h    доступ по индексу
std::cout << s.substr(0, 5) << "\n";     // → hello   substr возвращает тоже string_view — дёшево
std::cout << (s.find("txt") != std::string_view::npos) << "\n";   // → 1
std::cout << s.starts_with("hello") << "\n";   // → 1   (как у string)
std::cout << (s == "hello.txt") << "\n";       // → 1   сравнение работает
```

Уникальное для view — **дёшево двигать края окна**, не трогая данные: `remove_prefix(n)` сдвигает начало вправо, `remove_suffix(n)` — конец влево. Так, например, обрезают пробелы или отрезают уже разобранный кусок, без единой копии:

```cpp
std::string_view s = "  привет  ";
s.remove_prefix(2);   // окно поехало вправо на 2 — «съели» 2 ведущих пробела
s.remove_suffix(2);   // и с конца на 2 — теперь s смотрит ровно на "привет"
```

Чего нельзя — **менять** символы (`s[0] = 'H'` не скомпилируется) и **дописывать** (`+=` нет): view — только для чтения. Нужно изменить или накопить текст — это `std::string`.

### Главная ловушка: окно может повиснуть

`string_view` **не владеет** данными. Если строка, в которую он смотрит, перестала существовать, view указывает в никуда — это [висячая ссылка](10-slovar.md), как и у обычной ссылки, только её легче создать по неосторожности.

```cpp
std::string_view bad() {
  std::string local = "временная";
  return local;              // ❌ вернули окно в локальную строку —
}                            //    она умрёт на выходе, а view останется висеть
```

Та же беда — сохранить view от временного значения:

```cpp
std::string_view v = std::string("привет") + "!";   // ❌ временная строка тут же уничтожена,
std::cout << v;                                      //    v смотрит в мусор
```

Правило, снимающее почти все проблемы: **`string_view` — для параметров, а не для хранения.** Пришёл в функцию, попользовался, вышел — данные всё это время живы у вызывающего. Хранить текст «надолго» (в поле структуры, в векторе) — это `std::string`, который владеет своей копией.

Ещё тонкость: `string_view` **не обязан оканчиваться нулём**, поэтому отдавать его в старые C-функции (`printf("%s", …)`, что-то, что ждёт `const char*`) нельзя — для этого нужен `std::string` и его `.c_str()`.

### Когда брать `string_view`, а когда нет

| Бери `string_view` | Бери `std::string` |
|---|---|
| параметр функции, которая строку только **читает** | нужно **хранить** текст (поле, элемент вектора) |
| хочешь принимать и `string`, и литерал без копий | нужно **менять**/дописывать текст |
| режешь на подстроки (`substr` дёшев) | нужен `const char*` для C-функции (`.c_str()`) |

Практический вывод для твоего кода: там, где сейчас `const std::string&` у функции, которая ничего со строкой не делает, кроме чтения, — можно писать `std::string_view`. Для полей и любого хранения — по-прежнему `std::string`.

> `string_view` — про производительность и удобство приёма, а не про новые возможности. Пока строки короткие, выигрыш незаметен; ценность в единой подписи «принимаю любой текст». Что дальше по темам — [раздел 26](09-spravka.md#26-что-учить-дальше).
