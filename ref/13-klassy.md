## 22. Классы

В [разделе 19](08-struct-fayly.md#19-struct) уже сказано: как только у `struct` появляются методы, ты фактически пишешь класс — просто с открытыми полями. Класс добавляет к этому одну важную вещь: возможность **спрятать** данные, чтобы снаружи их нельзя было испортить.

> 📖 **Определение.** **Класс** — свой тип, который держит вместе данные (**поля**) и действия над ними (**методы**). **Объект** — конкретный экземпляр класса, созданный по этому «чертежу»: `Account acc;` — `acc` это объект. Термины собраны в [словаре](10-slovar.md#про-классы-ооп).

### От `struct` к `class`: одно отличие

Технически `struct` и `class` в C++ — почти одно и то же. Разница ровно одна: **что открыто по умолчанию.**

```cpp
struct Point {     // в struct всё public — открыто по умолчанию
  int x;
  int y;
};

class Secret {     // в class всё private — закрыто по умолчанию
  int hidden;      // снаружи не достать
};
```

Само по себе это мелочь. Смысл появляется, когда данные нужно **защитить правилом**.

### Инкапсуляция: спрятать данные, открыть действия

Представь счёт в банке. Баланс не должен становиться отрицательным. Со `struct` эту гарантию дать нельзя — поле открыто, и кто угодно испортит:

```cpp
struct Account {
  long long balance = 0;
};

Account acc;
acc.balance = -1000;      // ❌ ничто не мешает: инвариант «баланс >= 0» нарушен молча
```

Класс прячет поле (`private`) и разрешает менять его **только через свои методы** (`public`), которые следят за правилом:

```cpp
class Account {
 public:                       // ← отсюда и ниже — доступно снаружи
  void deposit(long long sum) {
    if (sum > 0)
      balance += sum;          // класс сам решает, как менять баланс
  }

 private:                      // ← отсюда и ниже — только внутри класса
  long long balance = 0;       // снаружи balance не увидеть и не присвоить
};

Account acc;
acc.deposit(100);              // ✅ так можно
acc.balance = -1000;           // ❌ error: 'balance' is private — правило не обойти
```

Это и есть **инкапсуляция**: данные спрятаны, наружу торчат только безопасные действия. Правило «баланс не бывает отрицательным» держится в одном месте, а не размазано по всей программе.

- **`private`** — видно только методам самого класса. Сюда прячут поля-данные.
- **`public`** — видно всем снаружи. Сюда выносят методы, через которые с объектом работают.

### Конструктор — как объект рождается

У `struct` поля задают при создании фигурными скобками: `Point p{3, 4}`. У класса с приватными полями так нельзя — они закрыты. Их задаёт **конструктор**: специальный метод с именем класса, который выполняется при создании объекта.

```cpp
class Account {
 public:
  Account(long long start) : balance(start) {}   // конструктор: имя класса, без типа возврата
  //      ↑ параметр        ↑ список инициализации: balance получает значение start

 private:
  long long balance = 0;
};

Account acc(500);        // конструктор вызвался, balance стал 500
```

Часть после двоеточия — **список инициализации**: поля получают значения ещё до входа в тело `{}`. Именно так и надо задавать поля — не присваиванием в теле:

```cpp
Account(long long start) : balance(start) {}   // ✅ инициализация — поле сразу правильное
Account(long long start) { balance = start; }  // ⚠️ работает, но поле сначала создаётся, потом присваивается
```

Для простых типов разница невелика, но привычка правильная: **инициализируй в списке, а не присваивай в теле.**

Конструкторов может быть несколько (перегрузка) — например, «с начальным балансом» и «с нуля»:

```cpp
class Account {
 public:
  Account() : balance(0) {}                      // без аргументов — пустой счёт
  Account(long long start) : balance(start) {}   // с начальным балансом

 private:
  long long balance = 0;
};

Account empty;         // вызвался Account()
Account rich(1000);    // вызвался Account(long long)
```

### `const`-методы — что только читает

Как и у [методов struct](08-struct-fayly.md#методы--функции-внутри-структуры), метод, который ничего не меняет, помечают `const`. Это позволяет звать его у `const`-объектов и защищает от случайной правки полей:

```cpp
class Account {
 public:
  long long getBalance() const {    // const: обещает не менять поля
    return balance;
    // balance += 1;                 // ❌ error: внутри const-метода поля менять нельзя
  }

 private:
  long long balance = 0;
};
```

Правило простое: **читающий метод — `const`, меняющий — без `const`.** Геттеры (методы «дай значение») почти всегда `const`.

### Деструктор и RAII

У конструктора есть пара — **деструктор**: метод `~ИмяКласса()`, который вызывается **сам**, когда объект выходит из области видимости. Это тот самый механизм, по которому закрываются файлы и освобождается память в `vector` — [RAII](10-slovar.md#про-типы-и-память).

```cpp
#include <iostream>
#include <string>
#include <utility>

class Scope {
 public:
  Scope(std::string name) : name_(std::move(name)) {
    std::cout << "+ " << name_ << "\n";   // конструктор — объект родился
  }
  ~Scope() {                              // ДЕСТРУКТОР — вызовется сам на выходе из области
    std::cout << "- " << name_ << "\n";
  }

 private:
  std::string name_;
};

int main() {
  Scope outer("main");
  {
    Scope inner("block");   // родится здесь
  }                         // и умрёт здесь — деструктор на закрывающей }
  std::cout << "работаем\n";
  return 0;
}                           // outer умрёт здесь
```

```
+ main
+ block
- block
работаем
- main
```

Порядок обратный рождению (`block` создан позже — уничтожен раньше), и деструктор срабатывает **на любом выходе** из блока: обычном, по `return`, даже при исключении. Поэтому в C++ ресурс освобождают **в деструкторе**, а не «не забыть в конце» — забыть невозможно.

> На практике свой деструктор нужен редко: готовые RAII-типы (`vector`, `string`, потоки, [умные указатели](18-umnye-ukazateli.md)) уже освобождают всё сами. Пиши деструктор, только когда класс владеет чем-то, что стандартная библиотека не закрывает за тебя. И помни: как только у класса появляется свой деструктор, стоит подумать и о копировании — это «правило трёх/пяти», тема на вырост.

### Пример целиком: класс `Account`

Всё вместе — маленький работающий класс с защищённым инвариантом:

```cpp
#include <iostream>

class Account {
 public:
  Account(long long start) : balance(start) {}   // счёт с начальным балансом

  void deposit(long long sum) {
    if (sum > 0)
      balance += sum;
  }

  bool withdraw(long long sum) {          // вернёт false, если денег не хватает
    if (sum <= 0 || sum > balance)
      return false;
    balance -= sum;
    return true;
  }

  long long getBalance() const {          // только читает — значит const
    return balance;
  }

 private:
  long long balance = 0;                  // спрятано: снаружи не испортить
};

int main() {
  Account acc(100);
  acc.deposit(50);
  std::cout << acc.getBalance() << "\n";              // → 150

  bool ok = acc.withdraw(500);                        // денег не хватает
  std::cout << ok << " " << acc.getBalance() << "\n"; // → 0 150   отказ, баланс цел

  // balance напрямую не тронуть — он private, инвариант «баланс >= 0» защищён
  return 0;
}
```

Обрати внимание: снаружи невозможно привести счёт в неверное состояние. Единственные способы тронуть баланс — `deposit` и `withdraw`, а они сами следят за правилами.

### `struct` или `class` — что когда

Выбор простой и не про синтаксис, а про смысл:

| Бери `struct` | Бери `class` |
|---|---|
| простой «мешок данных»: `Point`, `Student`, строка таблицы | у данных есть **правило** (инвариант), которое надо защищать |
| поля независимы, любое сочетание значений допустимо | неверное сочетание полей должно быть **невозможно** снаружи |
| нет логики или она в свободных функциях рядом | поведение и данные естественно живут вместе |

Пока задача — просто сложить несколько полей вместе (точка, запись о студенте), `struct` с открытыми полями честнее и короче. Класс достаёшь, когда появляется правило: «баланс не отрицателен», «проценты от 0 до 100», «список всегда отсортирован».

### Типовые ошибки

```cpp
// 1. Поле не инициализировано в конструкторе — внутри мусор
class Timer {
 public:
  Timer() {}          // ❌ seconds не задан → случайное значение
 private:
  int seconds;        // ✅ лечится так: int seconds = 0; (или в списке инициализации)
};

// 2. Сделал поле public «чтобы удобнее» — и потерял всю защиту
class Account {
 public:
  long long balance;  // ❌ снова кто угодно поставит -1000; инкапсуляция сломана
};

// 3. Забыл const на читающем методе
long long getBalance() { return balance; }   // ⚠️ без const — не вызвать у const-объекта
long long getBalance() const { return balance; }   // ✅
```

> Классы — это большая тема ([наследование](20-nasledovanie.md), деструкторы, `this`, операторы). Здесь показан фундамент: **спрятать данные, задать их конструктором, открыть безопасные методы.** Этого хватает, чтобы писать свои типы с защищённым состоянием; остальное добавится по мере надобности.
