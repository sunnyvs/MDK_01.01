# Задачник по C++ — путь изучения

Это не просто список задач, а **маршрут**: 9 основных тем от типов до файлов плюс
бонусная 10-я, каждая опирается на предыдущую. В каждой теме — по 8 задач (в теме про
баги — 7, в «перепиши» — 6), от разминочных 🟢 до сложных 🔴, с разбором «чему учит»
и «где пригодится», подсказками и мини тест-планом. **Готовых решений нет** — вы
сверяетесь с теорией справочника и собственным тест-планом.

Двигаясь по порядку, к концу вы соберёте рабочий набор навыков: посчитать, проверить,
перебрать, разложить на функции, сохранить в файл и починить чужой баг.

---

## Как устроен один шаг пути

Каждую тему проходите одним и тем же циклом — он и есть «путь изучения»:

```
1. ЧИТАЮ теорию      →  раздел справочника по теме (ссылки в таблице ниже)
2. СМОТРЮ пример     →  как приём выглядит в целой программе (examples/)
3. РЕШАЮ задачи      →  задачи темы, по нарастанию сложности (🟢 → 🔴)
4. ПРОВЕРЯЮ себя     →  мини тест-план в конце файла темы
5. ЧИНЮ баги         →  тема 9 (её берите параллельно, по мере сил)
```

Не пропускайте шаг 1: задачи специально построены на ловушках, разобранных в
справочнике. Решать, не прочитав теорию, — как собирать мебель, не открыв инструкцию.

> 📖 **Справочник и примеры — в этом же окне.** Карта всего — [Начни отсюда](../00-НАЧНИ-ОТСЮДА.md),
> теория по темам — в группе «Справочник по темам», готовые программы — в «Примеры программ».
> Подсказки к задачам ведут прямо на нужный раздел справочника.

## Как решать одну задачу (важно!)

Заведите под каждую задачу отдельный `.cpp` (например, `t1-1.cpp`) — так удобно
возвращаться к старым попыткам и сравнивать. Один заход — примерно 20–30 минут:

1. **Прочитайте условие → закройте файл.** Пишите по памяти, не подсматривая в пример.
2. **Соберите (`Ctrl+Alt+R`), добейтесь нуля предупреждений.** Предупреждение — это тоже баг, просто ещё не сработавший.
3. **Прогоните пример из условия.** Совпало — переходите к тест-плану.
4. **Прогоните мини тест-план темы** (внизу каждого файла) — там «злые» входы: пустой, ноль, отрицательное, очень большое. **Именно на краях программы ломаются.**
5. **Сломалось → найдите причину, а не просто почините.** Определите, к какому классу относится ошибка (см. тему 9).

**Порядок работы с подсказками** (не наоборот!):

1. Сначала решайте сами — минимум 15 минут.
2. Застряли → раскройте **«Подсказку»** (наводка на идею, без кода).
3. Всё ещё не выходит → перейдите по ссылке из подсказки в **теорию справочника** и разберите
   ловушку там. Готовых решений в задачнике нет намеренно — так задача действительно учит.

Застряли и после теории — покажите свой код и спросите, **на каком входе он ломается и почему**
(а не «дайте ответ»). Разбор собственного кода полезнее любого готового.

## Универсальный тест-план

Прежде чем сказать «работает», прогоните программу на этих входах — они ловят почти все типовые баги:

| Вход | Что проверяет |
|---|---|
| обычный пример из условия | базовая правильность |
| `0` | деление на ноль, пустой цикл, граница |
| отрицательное число | инициализация max/min, работа `%` |
| очень большое (`2000000000`, `10^18`) | переполнение `int`, выбор типа |
| буква вместо числа | сломанный `cin` (для задач с вводом) |
| пустой ввод / `N = 0` | цикл, который не должен выполниться |
| граничные значения (первый, последний, одинаковые) | ошибки «на единицу» |

## Если застряли

Порядок действий, прежде чем спрашивать:

1. **Прочитали сообщение компилятора целиком?** Первую ошибку, не последнюю.
2. **Поставили `F9` и посмотрели значения в панели Variables?** Половина «непонятных» багов видна за десять секунд.
3. **Вывели промежуточные значения?** `std::cout << "x = " << x << "\n";` — грубо, но работает.
4. **Проверили на самом простом входе?** Не на `12345`, а на `5`.

Не помогло — спрашивайте так, чтобы осталось чему научиться:

> «Вот задача 3.4 и мой код. Не переписывайте — скажите, на каком входе он ломается и почему.»

Показывайте свой код и просите объяснить **причину**, а не прислать готовый ответ. Иначе
научится тот, кто отвечает, а не вы.
