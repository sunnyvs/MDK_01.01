# Тема 1. Основы: типы, переменные, `const`

Это самый первый и самый важный кирпич. Почти все ошибки новичка растут отсюда:
«число вдруг стало отрицательным», «дробь округлилась в ноль», «ввёл цифру — получил
другую». Разобравшись с типами один раз, вы перестанете ловить эти баги случайно и
начнёте предвидеть их заранее.

## Чему вы здесь научитесь

- Выбирать правильный тип: `int`, `long long`, `double`, `char`, `std::string` — и понимать, **почему** именно его.
- Заранее видеть три классические ловушки: целочисленное деление, переполнение `int`, `char` как код символа.
- Управлять точностью вывода дробных чисел (`std::fixed`, `std::setprecision`).
- Давать числам имена через `const` — чтобы код объяснял себя сам.

## Где это пригодится

Это фундамент любой программы, которая что-то считает: средний балл, сумму в чеке,
проценты, координаты, время. Ошибка в выборе типа — самый частый «молчаливый» баг в
реальном коде: программа не падает, а просто выдаёт неверное число, и узнаёте вы об
этом последним.

## Как работать с темой

1. Прочитайте условие → **закройте файл** → пишите по памяти.
2. Соберите и запустите (`Ctrl+Alt+R`), добейтесь **нуля предупреждений**.

## 1.1. Средний чек 🟢

Даны суммы трёх покупок в рублях (целые числа). Напечатайте средний чек с одним
знаком после запятой.

**Формат ввода.** Три целых числа от 0 до 1 000 000, через пробел.

**Формат вывода.** Одно число — средний чек, ровно с одной цифрой после точки.

**Пример:**
```
Ввод
180 175 178
Вывод
177.7
```

**Что тренирует:** целочисленное деление против дробного, форматированный вывод.
**Где пригодится:** любое усреднение — чеки, оценки, показания датчиков, время отклика.
**Как подступиться:** сумма трёх `int` — тоже `int`; чтобы среднее получилось дробным, хотя бы один участник деления должен быть дробным.

> Осторожно: при делении трёх `int` на `3` результат будет целым — дробная часть потеряется.

## 1.2. Сосед по алфавиту 🟢

Дан один латинский символ и целое число `n`. Напечатайте символ, стоящий на `n`
позиций дальше в таблице символов.

**Формат ввода.** Символ (латинская буква) и целое число `n` (0 ≤ n ≤ 25), через пробел.

**Формат вывода.** Один символ.

**Пример 1:**
```
Ввод
a 3
Вывод
d
```
**Пример 2:**
```
Ввод
A 0
Вывод
A
```

**Что тренирует:** понимание, что `char` — это число (код символа), которое можно складывать.
**Где пригодится:** шифр Цезаря, генерация серийных номеров, перебор букв (A, B, C…), работа с таблицей символов.
**Как подступиться:** прибавьте `n` к символу и напечатайте результат **как символ**, а не как число.
**⭐ Бонус:** сделайте мини-шифр Цезаря — сдвиньте на `n` не один символ, а целую строку (`getline`), пробелы оставьте на месте.

## 1.3. Секундомер: чч:мм:сс 🟡

Дано время в секундах — одно целое число. Напечатайте его в формате `чч:мм:сс`,
каждое поле ровно в две цифры (например, `01:05:09`).

**Формат ввода.** Одно неотрицательное целое число — количество секунд (до 10^9).

**Формат вывода.** Строка вида `ЧЧ:ММ:СС`, где минуты и секунды — от 00 до 59, с ведущим нулём.

**Пример:**
```
Ввод
3909
Вывод
01:05:09
```

**Что тренирует:** цепочку из `/` и `%` (разбиение величины на несколько единиц) и вывод с ведущими нулями.
**Где пригодится:** таймеры, длительность видео и треков, логи, любое «большое число → часы/минуты/секунды».
**Как подступиться:** часы — это `/ 3600`; оставшиеся секунды — `% 3600`, из них минуты — `/ 60`, а секунды — `% 60`. Ведущий ноль даёт `std::setw(2)` и `std::setfill('0')` из `<iomanip>`.
**⭐ Бонус:** добавьте поддержку суток — формат `Д дн. ЧЧ:ММ:СС`, если время больше 24 часов.

## 1.4. Площадь и объём 🟡

Дан радиус. Напечатайте длину окружности, площадь круга и объём шара — каждое с
двумя знаками после запятой. Число π задайте как константу.

**Формат ввода.** Одно число (может быть дробным) — радиус, больше 0.

**Формат вывода.** Три числа через пробел: длина окружности `2πr`, площадь круга `πr²` и объём шара `4/3·πr³`, по два знака после точки.

**Пример:**
```
Ввод
2
Вывод
12.57 12.57 33.51
```

**Что тренирует:** `double`, именованные константы (`const`) и ту же ловушку целочисленного деления в коэффициенте `4/3`.
**Где пригодится:** любые формулы из физики, геометрии, финансов, где есть постоянный коэффициент (π, курс валют, ставка налога).
**Как подступиться:** радиус читайте в `double`; π заведите как `const double PI = 3.14159265358979;`. В объёме коэффициент пишите `4.0 / 3.0`, а не `4 / 3`, иначе он превратится в `1`.

> При радиусе `2` длина и площадь совпадают случайно. Проверьте на радиусе `1` и `3` — числа станут разными.

## 1.5. Найдите ошибку: сумма от 1 до n 🟡

Программа должна складывать все числа от 1 до `n`. Для маленьких `n` она работает,
а для `n` порядка 100000 выдаёт бессмыслицу (иногда отрицательную). Найдите причину
и исправьте.

```cpp
#include <iostream>

int main() {
  int n;
  std::cin >> n;
  int sum = 0;
  for (int i = 1; i <= n; ++i) {
    sum += i;
  }
  std::cout << sum << "\n";
}
```

**Формат ввода.** Одно целое число `n` (1 ≤ n ≤ 1 000 000).

**Формат вывода.** Сумма всех чисел от 1 до `n`.

**Пример:**
```
Ввод
100000
Вывод
5000050000
```

**Что тренирует:** распознавание переполнения `int` — самого коварного «молчаливого» бага.
**Где пригодится:** везде, где копится сумма или произведение больших чисел: счётчики, статистика, факториалы, суммы по большому массиву.
**Как подступиться:** программа логически верна, значит дело в **типе** накопителя. Прикиньте, какого размера будет ответ, и сравните с диапазоном `int` (примерно до 2,1 млрд).

## 1.6. Из Цельсия в Фаренгейт 🟢

Дана температура в градусах Цельсия. Напечатайте её в градусах Фаренгейта с одним
знаком после запятой. Формула: `F = C × 9/5 + 32`.

**Формат ввода.** Одно число (может быть дробным) — температура в Цельсиях.

**Формат вывода.** Одно число — температура в Фаренгейтах, один знак после точки.

**Пример 1:**
```
Ввод
100
Вывод
212.0
```
**Пример 2:**
```
Ввод
0
Вывод
32.0
```

**Что тренирует:** `double` и главную ловушку целочисленного деления в формуле.
**Где пригодится:** любой перевод единиц (валюты, меры измерения) — тот же класс формул.
**Как подступиться:** пишите `9.0 / 5.0`, а не `9 / 5`, иначе целочисленное деление даст `1`.
**⭐ Бонус:** добавьте Кельвин (`K = C + 273.15`) и найдите температуру, при которой шкалы Цельсия и Фаренгейта совпадают (подсказка: это −40).

## 1.7. Две скидки и округление 🔴

На товар действуют две скидки подряд: сначала первая, затем вторая — уже от
уменьшенной цены. Напечатайте итоговую цену, округлённую до копеек (двух знаков),
и суммарную «эффективную» скидку в процентах с одним знаком.

**Формат ввода.** Дробное число — цена, и два целых числа — проценты скидок (0 ≤ процент ≤ 100), через пробел.

**Формат вывода.** Две строки: `Цена: X` (два знака) и `Скидка: Y%` (один знак).

**Пример:**
```
Ввод
1000 20 20
Вывод
Цена: 640.00
Скидка: 36.0%
```

**Что тренирует:** последовательные проценты, дробную арифметику и корректное округление денег.
**Где пригодится:** магазины и маркетплейсы (акция + купон), налоги поверх наценки, сложные проценты.
**Как подступиться:** вторую скидку применяйте к уже уменьшенной цене, а не складывайте проценты. Эффективная скидка — это `(1 − итог/исходная) × 100`. Все деления держите дробными (`/ 100.0`).

> Две скидки по 20% дают не 40%, а 36% — именно поэтому их нельзя складывать.

## 1.8. Сумма квадратов 🔴

Напечатайте сумму `1² + 2² + … + n²`.

**Формат ввода.** Одно целое число `n` (1 ≤ n ≤ 1 000 000).

**Формат вывода.** Сумма квадратов всех чисел от 1 до `n`.

**Пример:**
```
Ввод
3
Вывод
14
```

**Что тренирует:** переполнение при умножении и приём `1LL *`.
**Где пригодится:** статистика (дисперсия, среднеквадратичное отклонение), физика, любые суммы произведений.
**Как подступиться:** ответ огромный — копите в `long long`, и само `i * i` считайте сразу в `long long`, иначе произведение переполнит `int` ещё до прибавления.
**⭐ Бонус:** проверьте себя формулой `n·(n+1)·(2n+1)/6` — результат обязан совпасть с циклом (и в формуле тоже держите `long long`).

> `14`, потому что `1 + 4 + 9 = 14`. При `n = 1 000 000` сумма — сотни триллионов.

# Подсказки

> 📖 Мало подсказки? Откройте теорию темы: [раздел справочника](../ref/01-osnovy.md).

<details>
<summary>1.1 — Средний чек</summary>

- Сумма трёх `int` — тоже `int`. Чтобы получить дробное среднее, приведите к дробному хотя бы одну часть: `(a + b + c) / 3.0` (делитель `3.0`, а не `3`).
- Один знак после точки: `#include <iomanip>` и `std::cout << std::fixed << std::setprecision(1) << avg;` либо `std::format("{:.1f}", avg)` из `<format>`.
</details>

<details>
<summary>1.2 — Сосед по алфавиту</summary>

- Символ — это число: `char c; std::cin >> c;`, затем `char result = c + n;` (компилятор может попросить `static_cast<char>(c + n)` — это нормально).
- Печатайте `result` как символ: `std::cout << result;`.
</details>

<details>
<summary>1.3 — Секундомер: чч:мм:сс</summary>

- Часы: `s / 3600`. Остаток: `s % 3600`. Из остатка минуты: `/ 60`, секунды: `% 60`.
- Ведущий ноль: `#include <iomanip>`, затем `std::cout << std::setfill('0') << std::setw(2) << h << ':' << std::setw(2) << m << ':' << std::setw(2) << sec;`.
- Секунд может быть до 10^9 — для часов это до ~277 тысяч, `int` справится, но `long long` надёжнее.
</details>

<details>
<summary>1.4 — Площадь и объём</summary>

- Радиус читайте в `double`. Длина `2 * PI * r`, площадь `PI * r * r`, объём `4.0 / 3.0 * PI * r * r * r`.
- Два знака: `std::fixed` + `std::setprecision(2)` (из `<iomanip>`), либо `std::format("{:.2f}", x)`.
- Коэффициент объёма — обязательно `4.0 / 3.0`: запись `4 / 3` даст `1`.
</details>

<details>
<summary>1.5 — Найдите ошибку: сумма от 1 до n</summary>

- Сумма 1..100000 — около 5 миллиардов; в `int` (примерно до 2,1 млрд) она **не помещается**, происходит переполнение — отсюда мусор и минусы.
- Замените тип накопителя: `long long sum = 0;`. Счётчик `i` можно оставить `int`.
- Это тот же класс ошибки, что и с факториалом: целочисленное переполнение.
</details>

<details>
<summary>1.6 — Из Цельсия в Фаренгейт</summary>

- Читайте `C` в `double`. Формула: `double f = c * 9.0 / 5.0 + 32;`.
- Именно `9.0 / 5.0`: запись `9 / 5` компилятор посчитает в целых числах и получит `1`.
- Один знак: `std::fixed` + `std::setprecision(1)`.
</details>

<details>
<summary>1.7 — Две скидки и округление</summary>

- Считайте по шагам: `double p1 = price * (100 - d1) / 100.0;`, затем `double p2 = p1 * (100 - d2) / 100.0;`.
- Эффективная скидка: `double eff = (1.0 - p2 / price) * 100.0;`.
- Вывод: `std::fixed` + `std::setprecision(2)` для цены и `setprecision(1)` для скидки (точность можно переключать по ходу вывода).
</details>

<details>
<summary>1.8 — Сумма квадратов</summary>

- Накопитель `long long sum = 0;`.
- В цикле: `sum += 1LL * i * i;`. Приставка `1LL` превращает умножение в `long long` — иначе `i * i` для больших `i` переполнит `int` ещё до прибавления.
</details>

## Проверьте себя (мини тест-план)

Прежде чем считать тему закрытой, прогоните свои решения на «злых» входах:

- **1.1:** одинаковые числа (`180 180 180` → `180.0`, а не `180`); убедитесь, что знак после точки ровно один.
- **1.3:** `0` → `00:00:00`; ровно час (`3600` → `01:00:00`); проверьте ведущие нули у минут и секунд.
- **1.4:** радиус `1` и `3` — все три числа должны стать разными; объём при `r = 2` равен `33.51`.
- **1.5:** `n = 1` (ответ `1`); `n = 1000000` (ответ должен быть огромным и положительным).
- **1.6:** `0` → `32.0`; отрицательная температура (`-40` → `-40.0` — точка совпадения шкал).
- **1.7:** скидки `0 0` (цена без изменений, скидка `0.0%`); `50 50` (итог — четверть цены, скидка `75.0%`).
- **1.8:** `n = 1` → `1`; `n = 1000000` — число должно быть огромным и положительным (тест на `long long`).
