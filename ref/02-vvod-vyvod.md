## 4. Ввод и вывод

### Базовый вывод

```cpp
int x = 5;
double y = 3.5;
std::string name = "Аня";

std::cout << "Текст " << x << " и " << y << "\n";   // << можно сцеплять сколько угодно раз
// → Текст 5 и 3.5

std::cout << name << ", тебе " << x << " лет\n";
// → Аня, тебе 5 лет
```

`"\n"` быстрее `std::endl`: `endl` дополнительно сбрасывает буфер на диск, что в цикле заметно тормозит. Бери `endl` только когда нужно увидеть вывод немедленно — например, перед долгим расчётом.

### Базовый ввод и почему он опасен

```cpp
int n = 0;
std::cin >> n;                   // пользователь ввёл: abc

std::cout << n << "\n";          // → 0   значение не изменилось
std::cin >> n;                   // ❌ и это чтение тоже не сработает — и все следующие
```

Один неверный ввод переводит поток в состояние ошибки, и **все последующие `cin >>` молча ничего не читают**. Программа досчитывает до конца на нулях и выдаёт бессмыслицу.

**Что именно окажется в переменной — зависит от того, чем ввод был плох.** Проверено на твоём компиляторе:

| Пользователь ввёл | Чтение | Значение переменной стало |
|---|---|---|
| `abc` | провалилось | `0` |
| `99999999999999999999` (больше `int`) | провалилось | `2147483647` — то есть `INT_MAX` |
| `-99999999999999999999` | провалилось | `-2147483648` — то есть `INT_MIN` |

Второй и третий случай коварнее первого: переменная получает **предельное, но правдоподобное** число. Программа без проверки чтения посчитает с ним и выдаст ответ, который выглядит настоящим. Именно поэтому результат `cin >>` надо проверять всегда, а не полагаться на «там будет ноль».

### Безопасное чтение — держи под рукой

```cpp
#include <cstdlib>          // std::exit
#include <iostream>
#include <limits>
#include <string>

int readInt(const std::string &prompt) {   // const & — строка не копируется и не меняется
  int value = 0;
  while (true) {                           // крутимся, пока не получим корректное число
    std::cout << prompt;                   // печатаем приглашение заново на каждой попытке
    if (std::cin >> value)                 // >> вернул поток; поток в bool = «чтение удалось?»
      return value;                        // удалось — сразу выходим из функции

    if (std::cin.eof()) {                  // ввод кончился совсем (Ctrl+Z или файл дочитан)
      std::cout << "\nВвод закончился.\n"; // ⚠️ без этой проверки цикл станет БЕСКОНЕЧНЫМ
      std::exit(0);
    }

    std::cin.clear();                      // снимаем флаг ошибки (ввод при этом НЕ чистится)
    std::cin.ignore(                       // выбрасываем всё, что осталось в буфере,
        std::numeric_limits<std::streamsize>::max(), '\n');   // до конца строки
    std::cout << "Нужно ввести целое число. Попробуйте снова.\n";
  }
}
```

```
Ввод:   abc
Вывод:  Нужно ввести целое число. Попробуйте снова.
Ввод:   12
Итог:   функция вернула 12
```

Почему порядок именно такой:

| Строка | Что было бы без неё |
|---|---|
| `if (std::cin >> value)` | не узнаешь, что чтение провалилось |
| `if (std::cin.eof())` | при конце ввода **бесконечный цикл**: `clear` снимает флаг, читать нечего, и так вечно |
| `std::cin.clear()` | поток остаётся «сломанным», `ignore` ничего не сделает, цикл станет бесконечным |
| `std::cin.ignore(...)` | буква `abc` останется в буфере, следующая попытка прочитает её же — снова бесконечный цикл |

> **Про проверку `eof` подробнее.** Пока ты вводишь руками, конец ввода не наступает — и кажется, что проверка лишняя. Но стоит нажать **Ctrl+Z** (конец ввода в Windows) или запустить программу с файлом вместо клавиатуры (`main.exe < input.txt`), как поток закрывается навсегда. Тогда `>>` проваливается **каждый раз**, `clear()` честно снимает флаг, читать по-прежнему нечего — и программа бесконечно печатает «Нужно ввести целое число», пока её не убьют. Проверено: без этих трёх строк программа зависает намертво.
>
> `std::exit(0)` — единственное место, где выход посреди программы оправдан: продолжать всё равно нечем. Когда дойдёшь до исключений, эту функцию будет правильнее написать через `throw` или `std::optional`.

### Разные ситуации ввода

**Число в заданном диапазоне:**

```cpp
int readIntInRange(const std::string &prompt, int lo, int hi) {
  while (true) {
    int value = readInt(prompt);              // сначала гарантируем, что это вообще число
    if (value >= lo && value <= hi)           // потом проверяем диапазон
      return value;
    std::cout << "Нужно число от " << lo << " до " << hi << "\n";
  }
}

int age = readIntInRange("Возраст: ", 1, 120);
```

**Строка целиком, вместе с пробелами:**

```cpp
std::string fullName;
std::cout << "ФИО: ";
std::getline(std::cin, fullName);       // getline читает ВСЮ строку до Enter
std::cout << fullName << "\n";
// Ввод:  Иванов Иван Иванович
// →      Иванов Иван Иванович

std::cin >> fullName;                   // ❌ так прочитается только "Иванов" —
                                        //    >> останавливается на первом пробеле
```

**Смесь `>>` и `getline` — главная ловушка:**

```cpp
int age = 0;
std::string name;

std::cout << "Возраст: ";
std::cin >> age;                          // прочитали 25, но Enter остался в буфере!

std::cout << "Имя: ";
std::getline(std::cin, name);             // ❌ getline тут же читает этот Enter
std::cout << "[" << name << "]\n";        // → []   пустая строка, приглашение промелькнуло
```

```cpp
std::cin >> age;
std::cin.ignore(10000, '\n');             // ✅ выбросили остаток строки вместе с Enter
std::getline(std::cin, name);             // теперь читается по-настоящему
std::cout << "[" << name << "]\n";        // → [Аня]
```

**Почему так происходит — картинка буфера:**

```
   Пользователь набрал:   25⏎Аня⏎

   Буфер ввода:   [ 2 ][ 5 ][ ⏎ ][ А ][ н ][ я ][ ⏎ ]
                   └──┬──┘
                      │
   std::cin >> age    ─┘  забирает 25 и останавливается ПЕРЕД ⏎
                          (>> не трогает перевод строки)

   Осталось в буфере:      [ ⏎ ][ А ][ н ][ я ][ ⏎ ]
                            ↑
   std::getline(...)  ──────┘  читает всё до первого ⏎
                               а он тут же — значит строка ПУСТАЯ
```

`std::cin.ignore(10000, '\n')` выбрасывает этот застрявший `⏎`, и следующий `getline` читает уже настоящую строку.

**Читать числа, пока не кончатся:**

```cpp
int x = 0;
int sum = 0;
while (std::cin >> x)         // цикл закончится на первом нечисле или на конце ввода (Ctrl+Z)
  sum += x;
std::cout << "Сумма: " << sum << "\n";
// Ввод:  1 2 3 4 5 <Ctrl+Z>
// →      Сумма: 15
```

**Читать строки, пока не кончатся:**

```cpp
std::string line;
int lineNumber = 1;
while (std::getline(std::cin, line)) {          // getline тоже возвращает поток
  std::cout << lineNumber << ": " << line << "\n";
  ++lineNumber;
}
```

### Разбор строки: `std::istringstream`

Часто удобнее сначала прочитать **всю строку** через `getline`, а потом разобрать её на части. Для этого строку превращают в поток — `std::istringstream` из `<sstream>`: из него читают тем же `>>`, что и из `std::cin`.

```cpp
#include <iostream>
#include <sstream>          // std::istringstream
#include <string>
#include <vector>

int main() {
  std::string line = "10 20 30 40";
  std::istringstream in(line);       // строка «притворяется» потоком ввода

  std::vector<int> nums;
  int x = 0;
  while (in >> x)                    // читаем из строки ровно как из std::cin
    nums.push_back(x);

  std::cout << "чисел: " << nums.size() << "\n";   // → чисел: 4
  return 0;
}
```

Зачем так, если можно сразу `std::cin >> x`? Когда в одной строке — заранее неизвестное число значений, а следующая строка это уже другая запись. `getline` берёт строку целиком, а `istringstream` даёт разобрать её, не залезая в следующую.

У `getline` есть третий аргумент — **свой разделитель**. Так строку режут по `;` или `,` (основа разбора CSV — см. пример [Расходы из CSV](../examples/05-raskhody-csv.md)):

```cpp
#include <iostream>
#include <sstream>
#include <string>

int main() {
  std::string row = "Аня;95;отлично";
  std::istringstream in(row);
  std::string field;
  while (std::getline(in, field, ';'))    // читаем до каждого ';'
    std::cout << "[" << field << "]";
  std::cout << "\n";                        // → [Аня][95][отлично]
  return 0;
}
```

> Тот же приём работает и с файлом: вместо `istringstream` берут `std::ifstream` и читают из него точно так же — построчно `getline`, а строку разбирают `istringstream`. Подробнее — в разделе [работа с файлами](08-struct-fayly.md).

### Строка и число: `std::stoi` и `std::to_string`

Когда число пришло **уже как текст** (из строки, файла, аргумента), его переводят в число функциями из `<string>`, а обратно — `std::to_string`:

```cpp
#include <iostream>
#include <string>

int main() {
  int n = std::stoi("42");                 // строка → int   (есть stol, stoll для длинных)
  double d = std::stod("3.14");            // строка → double
  std::string s = std::to_string(n * 2);   // число → строка

  std::cout << n << " " << d << " " << s << "\n";   // → 42 3.14 84
  return 0;
}
```

Важный нюанс: `std::stoi` **бросает исключение**, если текст — не число:

```cpp
int bad = std::stoi("abc");   // ❌ во время работы: исключение std::invalid_argument, программа падает
```

Поэтому для **интерактивного** ввода надёжнее `readInt` из раздела выше: он проверяет ввод в цикле и не роняет программу. А `stoi`/`stod` бери, когда строка уже есть и ты либо уверен в её содержимом, либо готов ловить ошибку — как это делать, в разделе про [исключения](14-isklyucheniya.md).

### Форматирование вывода

```cpp
#include <iomanip>

double pi = 3.14159265;

std::cout << pi << "\n";                                  // → 3.14159   (по умолчанию 6 цифр)
std::cout << std::fixed << std::setprecision(2) << pi;    // → 3.14      (фиксированные 2 знака)
std::cout << "\n";

// setw — ширина поля, удобно для таблиц
std::cout << std::setw(10) << "Имя" << std::setw(6) << "Балл" << "\n";
std::cout << std::setw(10) << "Аня"  << std::setw(6) << 95    << "\n";
std::cout << std::setw(10) << "Борис"<< std::setw(6) << 7     << "\n";
// →        Имя  Балл
// →        Аня    95
// →      Борис     7
```

| Манипулятор | Что делает | Действует |
|---|---|---|
| `std::fixed` | всегда столько знаков после точки, сколько задано | до отмены |
| `std::setprecision(n)` | количество знаков | до отмены |
| `std::setw(n)` | ширина поля для **следующего** значения | только на одно значение |
| `std::left` / `std::right` | выравнивание внутри поля | до отмены |
| `std::boolalpha` | печатать `true`/`false` вместо `1`/`0` | до отмены |

### `std::format` — современный способ (C++20)

Всё, что выше, — классика из старых учебников: она работает, и её надо уметь читать. Но с C++20 у форматирования есть **вторая, гораздо более удобная запись**, и твой компилятор (g++ 15.2) её поддерживает.

```cpp
#include <format>

std::cout << std::format("{} + {} = {}\n", 2, 3, 5);        // → 2 + 3 = 5
//                        ↑    ↑    ↑
//              {} — «сюда подставь очередной аргумент», по порядку

std::cout << std::format("{:.2f}\n", 3.14159);              // → 3.14   два знака после точки
std::cout << std::format("{:>10}|\n", "право");             // →      право|   вправо в поле 10
std::cout << std::format("{:<10}|\n", "лево");              // → лево      |   влево
std::cout << std::format("{:^10}|\n", "центр");             // →   центр   |   по центру
std::cout << std::format("{:05}\n", 42);                    // → 00042    дополнить нулями
std::cout << std::format("{}\n", true);                     // → true     сразу словом, без boolalpha
```

Главное отличие от `<<`: **строка целиком видна как строка**, а не разорвана стрелочками. Сравни одно и то же:

```cpp
// Через <<: настройки перемешаны с данными, легко потерять что-то в цепочке
std::cout << std::fixed << std::setprecision(2) << "Средний балл: " << avg << "\n";

// Через format: слева — как выглядит результат, справа — откуда взять значения
std::cout << std::format("Средний балл: {:.2f}\n", avg);
```

**Ещё удобство: `setprecision` действует до отмены, а `{:.2f}` — только здесь.** Это источник обидных багов: настроил два знака для одного числа, а потом все остальные числа в программе печатаются округлёнными.

```cpp
std::cout << std::fixed << std::setprecision(2);
std::cout << 3.14159 << "\n";        // → 3.14   этого и хотели
std::cout << 1000.5 << "\n";         // → 1000.50   ⚠️ а вот это уже сюрприз
std::cout << 7 / 3.0 << "\n";        // → 2.33      и это тоже — настройка осталась включённой

std::cout << std::format("{:.2f}\n", 3.14159);   // → 3.14
std::cout << 1000.5 << "\n";                     // → 1000.5   ✅ ничего не сломалось
```

#### Почему это важно именно для русских таблиц

`setw` считает **байты**, а не буквы. Кириллица в UTF-8 занимает по два байта — поэтому таблица с русскими именами разъезжается:

```cpp
std::cout << std::setw(10) << "Имя"   << std::setw(6) << 95 << "|\n";
std::cout << std::setw(10) << "Борис" << std::setw(6) << 7  << "|\n";
std::cout << std::setw(10) << "Bob"   << std::setw(6) << 7  << "|\n";
```

```
    Имя    95|          ← «Имя» = 6 байт, отступ съеден
Борис     7|            ← «Борис» = 10 байт, поле кончилось, столбец уехал
       Bob     7|       ← а латиница встала ровно
```

`std::format` считает **символы**, и та же таблица выходит ровной:

```cpp
std::cout << std::format("{:>10}{:>6}|\n", "Имя", 95);
std::cout << std::format("{:>10}{:>6}|\n", "Борис", 7);
std::cout << std::format("{:>10}{:>6}|\n", "Bob", 7);
```

```
       Имя    95|
     Борис     7|
       Bob     7|
```

Практический вывод: **таблицу с русскими подписями делай через `std::format`.** Через `setw` она ровной не станет никакими стараниями.

#### Табличка формата

Здесь `·` — это пробел, показанный точкой, чтобы было видно, где он появляется.

| Запись | Что делает | Пример → результат |
|---|---|---|
| `{}` | подставить как есть | `format("{}", 42)` → `42` |
| `{:.2f}` | дробное, 2 знака после точки | `format("{:.2f}", 3.14159)` → `3.14` |
| `{:5}` | поле шириной 5 (числа жмутся вправо) | `format("{:5}", 42)` → `···42` |
| `{:<5}` | влево | `format("{:<5}", 42)` → `42···` |
| `{:>5}` | вправо | `format("{:>5}", 42)` → `···42` |
| `{:^5}` | по центру | `format("{:^5}", 42)` → `·42··` |
| `{:05}` | дополнить нулями | `format("{:05}", 42)` → `00042` |
| `{:*^9}` | заполнить своим символом | `format("{:*^9}", "меню")` → `**меню***` |
| `{1} {0}` | взять аргументы в своём порядке | `format("{1} {0}", "мир", "Привет")` → `Привет мир` |

Формат умеет и просто **собрать строку**, не печатая её:

```cpp
std::string line = std::format("{}: {} баллов", "Аня", 95);
std::cout << line << "\n";                     // → Аня: 95 баллов
```

Раньше для этого приходилось городить `std::ostringstream`, теперь — одна строка.

**Вывод таблицы студентов целиком:**

```cpp
struct Student { std::string name; int score = 0; };
std::vector<Student> group = {{"Аня", 95}, {"Борис", 70}, {"Вика", 8}};

std::cout << std::format("{:<10}{:>5}\n", "Имя", "Балл");   // шапка
std::cout << std::format("{:-<15}\n", "");                  // линия из дефисов
for (const auto &s : group)
  std::cout << std::format("{:<10}{:>5}\n", s.name, s.score);
```

```
Имя        Балл
---------------
Аня           95
Борис         70
Вика           8
```

> **Когда формат не соберётся.** Строка формата проверяется **на этапе компиляции** — это плюс: опечатку поймаешь сразу, а не в работающей программе. Если аргументов меньше, чем `{}`, будет ошибка сборки, а не мусор на экране. Только помни: `std::format` требует `-std=c++20` и GCC 13 и новее (у тебя 15.2 — всё в порядке). На чужом старом компиляторе он может не собраться, и тогда откатываешься на `setw`/`setprecision` — потому знать надо оба способа.

### Печать округляет, а не меняет число

`{:.2f}` и `setprecision` влияют только на то, как число **выглядит на экране**. Само значение в переменной не меняется — там по-прежнему все цифры. Это прямое продолжение [ловушки с точностью дробных](01-osnovy.md#ловушка-4-дробные-числа-и-точность): нельзя судить о значении по напечатанному виду.

```cpp
#include <format>
#include <iostream>

int main() {
  double price = 3.14159;
  std::cout << std::format("{:.2f}\n", price);   // → 3.14      на экране округлено до 2 знаков
  std::cout << std::format("{}\n", price);       // → 3.14159   в переменной те же цифры

  std::cout << std::format("{:+}\n", 42);        // → +42       всегда со знаком (для −, 0, +)
  std::cout << std::format("{:.0f}\n", 2.7);     // → 3         ноль знаков — округление до целого
  return 0;
}
```

Практический вывод: **округляй только при выводе, а считай по полному значению.** Если округлить само число (например, сложить копейки из округлённых рублей), ошибка накопится. Храни точное, показывай округлённое.
