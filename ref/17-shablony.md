## 32. Шаблоны

### Проблема: одна логика, три копии

В [разделе 9](04-funkcii.md#перегрузка-одно-имя-разные-аргументы) `maxOf` пришлось написать трижды — для `int`, `double` и строки:

```cpp
int maxOf(int a, int b)             { return (a > b) ? a : b; }
double maxOf(double a, double b)    { return (a > b) ? a : b; }
std::string maxOf(const std::string &a, const std::string &b) { return (a > b) ? a : b; }
```

Тело у всех **одинаковое** — меняется только тип. Копировать один и тот же код ради типа — ровно то, чего мы избегаем. Шаблон пишет эти версии за тебя.

### `template` — функция с «дыркой под тип»

Шаблон — это функция, где тип оставлен «дыркой» с именем (обычно `T`), а компилятор подставляет настоящий тип при вызове:

```cpp
#include <iostream>
#include <string>

template <typename T>            // T — любой тип, подставится при вызове
T maxOf(T a, T b) {
  return (a > b) ? a : b;
}

int main() {
  std::cout << maxOf(3, 7) << "\n";        // T = int    → 7
  std::cout << maxOf(3.5, 2.1) << "\n";    // T = double → 3.5
  std::cout << maxOf(std::string("аб"), std::string("вг")) << "\n";  // T = string → вг
  return 0;
}
```

Одно тело — три применения. Тип `T` компилятор **выводит сам** из аргументов: передал два `int` — `T` стал `int`.

### Как это работает: инстанцирование

Шаблон — это не готовая функция, а **рецепт**. Когда ты зовёшь `maxOf(3, 7)`, компилятор по рецепту «штампует» настоящую функцию для `int`; на `maxOf(3.5, 2.1)` — отдельную для `double`. Это называется **инстанцирование**.

Отсюда — две вещи, которые ты уже видел:

- **Ошибки в шаблонах выходят на пол-экрана.** Компилятор ругается уже в момент «штамповки», в глубине рецепта. Как их читать — [раздел 27](11-oshibki.md#страшные-ошибки-на-пол-экрана): ищи первую строку со своим типом.
- **Код шаблона живёт в заголовках.** Чтобы «штамповать» под нужный тип, компилятору нужно **тело** шаблона в каждом месте вызова — поэтому шаблоны не разносят на `.h`/`.cpp`, как обычные функции, а пишут целиком в заголовке.

### Требование к типу: он должен «уметь» нужное

Шаблон подставит **любой** тип — но только если тот умеет всё, что тело от него хочет. `maxOf` использует `>`, значит тип обязан уметь сравниваться:

```cpp
struct Point { int x, y; };

maxOf(Point{1, 2}, Point{3, 4});   // ❌ ошибка: у Point нет operator> — сравнивать нечем
```

Это тот же случай, что «[свой `struct` как ключ `map`](06-konteynery.md#свой-struct-как-ключ)»: контейнеры и алгоритмы — шаблоны, и если твой тип не умеет `<` или `>`, ошибка приходит из их глубины. Добавь нужный оператор — и тип «подойдёт».

### `concepts`: понятные требования к типу

Проблема шаблонных ошибок в том, что требование «тип должен уметь `>`» нигде не написано — оно спрятано в теле, и нарушение вылезает простынёй из глубины. **Концепты** (C++20) позволяют указать требование **прямо в объявлении** — тогда ошибка становится короткой и по делу:

```cpp
#include <concepts>
#include <iostream>

template <std::totally_ordered T>     // T обязан уметь сравниваться (< > ==)
T maxOf(T a, T b) {
  return (a > b) ? a : b;
}

int main() {
  std::cout << maxOf(3, 7) << "\n";   // → 7
  return 0;
}
```

Теперь вызов `maxOf` с типом без сравнения даёт понятное «constraint not satisfied: тип не удовлетворяет `totally_ordered`», а не десять экранов внутренностей. Готовых концептов в `<concepts>` много: `std::integral` (целые), `std::floating_point` (дробные), `std::totally_ordered` (сравнимые). Свои требования тоже можно описывать через `requires`, но на первое время хватает готовых.

### Шаблонные структуры

Шаблоном может быть не только функция, но и тип. Именно так устроены `std::vector<T>` и `std::pair<A, B>` — один рецепт, разные подстановки:

```cpp
template <typename T>
struct Box {                 // коробка, в которой лежит что угодно одного типа
  T value;
  bool empty = true;
};

Box<int> a{42, false};           // коробка с int
Box<std::string> b{"текст", false};   // коробка со строкой
std::cout << a.value << " " << b.value;   // → 42 текст
```

Параметров-типов может быть несколько — как у `std::map<K, V>`:

```cpp
template <typename K, typename V>
struct Pair {
  K key;
  V value;
};
```

### Когда писать свой шаблон, а когда нет

| Пиши шаблон | Не пиши |
|---|---|
| **одна и та же** логика нужна для многих типов (утилита, контейнер, алгоритм) | функция и так работает с одним типом — шаблон только усложнит |
| тип не важен, важно поведение (`>`, перебор, вывод) | «на будущее, вдруг пригодится» — обобщать заранее не надо |
| так убираешь дублирование, как с тремя `maxOf` | ради одного вызова с одним типом |

Пока задачи учебные, свои шаблоны нужны редко — гораздо чаще ты **пользуешься** чужими (`vector`, `sort`, `optional`). Свой пиши, когда ловишь себя на копировании функции ради смены типа — как раз случай `maxOf`.

> Шаблоны — большая тема (шаблонные методы, специализация, `concepts` из C++20, которые делают требования к типу явными и ошибки — понятными). Здесь показан фундамент: **одно тело, тип-параметр `T`, компилятор штампует версии**. Этого достаточно, чтобы убирать дублирование по типу и понимать, откуда берутся длинные ошибки контейнеров.
