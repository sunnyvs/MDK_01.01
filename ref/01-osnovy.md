## 1. Каркас и сборка

### Минимальная программа

```cpp
#include <iostream>     // подключает cin и cout — без этого компилятор их не знает
#include <windows.h>    // только Windows: отсюда берутся SetConsoleCP и CP_UTF8

int main() {                    // main — точка входа, откуда программа стартует
  SetConsoleCP(CP_UTF8);        // консоль будет ПОНИМАТЬ русский ввод
  SetConsoleOutputCP(CP_UTF8);  // консоль будет ПОКАЗЫВАТЬ русский вывод

  std::cout << "Привет\n";      // << отправляет текст в поток вывода, \n — перевод строки
  return 0;                     // 0 = «завершилась без ошибок», это видит система
}
```

`int main()` — именно `int`, никогда `void main()`. Возвращаемое число называется **кодом возврата**: `0` — успех, любое другое — «что-то пошло не так». Пользователь его не видит, но система и скрипты — да.

### Скелет любой учебной задачи

Почти всё, что ты пишешь, укладывается в три части. Держи эту структуру — с ней проще отлаживать:

```cpp
#include <iostream>
#include <windows.h>

int main() {
  SetConsoleCP(CP_UTF8);
  SetConsoleOutputCP(CP_UTF8);

  // --- 1. ВВОД: получили данные -------------------------------
  int a = 0;                             // всегда с начальным значением
  int b = 0;
  std::cout << "Введите два числа: ";    // приглашение — пользователь должен понимать, чего от него ждут
  std::cin >> a >> b;                    // можно читать несколько значений подряд

  // --- 2. РАСЧЁТ: посчитали ----------------------------------
  int sum = a + b;                       // вся логика — здесь, между вводом и выводом
  int product = a * b;

  // --- 3. ВЫВОД: показали ------------------------------------
  std::cout << "Сумма: " << sum << "\n";
  std::cout << "Произведение: " << product << "\n";

  return 0;
}
```

```
Ввод:   3 4
Вывод:  Сумма: 7
        Произведение: 12
```

> Почему это важно: когда ввод, расчёт и вывод перемешаны, ошибку ищешь по всей программе. Когда разделены — сразу видно, на каком из трёх этапов сломалось.

### Сборка

В VS Code — **`Ctrl+Alt+R`** (расширение C/C++ Runner, флаги уже прописаны в `.vscode/settings.json`).
Руками из терминала:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -g -O0 -o main.exe main.cpp
./main.exe
```

| Флаг | Что делает |
|---|---|
| `-std=c++20` | версия языка. Без него g++ возьмёт свою по умолчанию |
| `-o main.exe` | имя результата (иначе получится `a.exe`) |
| `-Wall -Wextra` | предупреждения — **всегда** |
| `-Wpedantic` | придирки к нестандартному коду |
| `-Wshadow` | одна переменная перекрывает другую с тем же именем |
| `-Wconversion` `-Wsign-conversion` | незаметное сужение типа, потеря знака |
| `-g -O0` | отладочная информация, без оптимизации — для пошаговой отладки |
| `-O2` | оптимизация — для готовой программы |
| `-D_GLIBCXX_ASSERTIONS` | проверки во время работы внутри `vector`, `string`, `map` — см. ниже |

### Флаг, который ловит выход за границы

Обычное `v[5]` у вектора из трёх элементов — молчаливая порча памяти: ни ошибки, ни падения, просто мусор. Один флаг превращает это в внятное сообщение:

```bash
g++ -std=c++20 -Wall -Wextra -D_GLIBCXX_ASSERTIONS -g -O0 -o main.exe main.cpp
```

```cpp
std::vector<int> v = {1, 2, 3};
std::cout << v[5];       // без флага: мусор, программа спокойно идёт дальше
                         // с флагом:  Assertion '__n < this->size()' failed.
```

Сообщение называет и файл стандартной библиотеки, и нарушенное условие. Держи флаг включённым, пока учишься: он стоит почти ничего, а ловит целый класс ошибок, которые иначе ищешь часами.

> **Про `-fsanitize=address`,** который советуют почти во всех руководствах: в MSYS2 / MinGW он **не собирается** — линковщик выдаст `ld returned 5 exit status`. Это особенность сборки GCC под Windows, а не твоя ошибка. Санитайзеры живут на Linux и в MSVC; здесь их роль играет `-D_GLIBCXX_ASSERTIONS`.

### Как читать ошибку компилятора

Ошибки читаются **сверху вниз, и только первая**. Остальные обычно — её последствия.

```
main.cpp:12:15: error: 'city' was not declared in this scope
   12 |   std::cout << city;
      |                ^~~~
```

| Часть | Что значит |
|---|---|
| `main.cpp:12:15` | файл, строка 12, символ 15 — щёлкни, VS Code прыгнет туда |
| `error:` | ошибка, программа не собралась. `warning:` — собралась, но подозрительно |
| `'city' was not declared` | суть: имени `city` в этом месте не существует |
| `^~~~` | стрелка показывает точное место |

Три самые частые формулировки:

| Сообщение | Что произошло |
|---|---|
| `was not declared in this scope` | опечатка в имени, либо переменная объявлена ниже/в другом блоке |
| `expected ';' before ...` | забытая точка с запятой — обычно на **предыдущей** строке |
| `no matching function for call to ...` | функция есть, но аргументы не того типа или не в том количестве |

### Отладчик: увидеть, что происходит внутри

Самый частый способ понять, почему программа врёт, — натыкать `std::cout` в подозрительные места. Он работает, но у него есть предел: печатаешь то, о чём догадался заранее, а потом эти строки надо убирать. Отладчик показывает **все** переменные в любой момент, ничего не добавляя в код.

У тебя всё уже установлено: gdb 17.1 идёт вместе с MSYS2, а `launch.json` расширение создаёт само.

#### Три шага, чтобы начать

1. **Поставь точку останова** — щёлкни слева от номера строки (появится красный кружок) или нажми `F9`. Программа замрёт **перед** выполнением этой строки.
2. **Запусти отладку** — `Ctrl+Alt+D` (это `Debug Single File`, отладочный близнец привычного `Ctrl+Alt+R`).
3. **Смотри панель Variables** слева: там все переменные, видимые в текущий момент, с их настоящими значениями.

> ⚠️ Отлаживать надо сборку с флагом `-g` (без оптимизаций). `Ctrl+Alt+D` делает это сам, но если в строке состояния расширения выбран режим `Release`, переключи на `Debug` — иначе отладчик будет прыгать по строкам как попало: оптимизатор переставил код.

#### Клавиши, которых хватит на всё

| Клавиша | Что делает | Когда нажимать |
|---|---|---|
| `F9` | поставить/убрать точку останова | до запуска |
| `Ctrl+Alt+D` | запустить отладку текущего файла | вместо `Ctrl+Alt+R` |
| `F10` | **шаг через** — выполнить строку целиком | обычное движение по программе |
| `F11` | **шаг внутрь** — зайти в вызываемую функцию | хочу посмотреть, что внутри `readInt` |
| `Shift+F11` | выйти из функции наружу | насмотрелся, верни обратно |
| `F5` | продолжить до следующей точки останова | пропустить скучное место |
| `Shift+F5` | остановить отладку | всё, понял |

`F10` и `F11` различаются одним: на строке `int x = readInt("N: ");` **F10** выполнит функцию целиком и покажет результат, а **F11** прыгнет внутрь `readInt` и даст пройти её построчно.

#### Что видно в панели Variables

Отладчик умеет показывать контейнеры по-человечески — проверено на твоей сборке gdb:

```cpp
std::vector<int> v = {10, 20, 30};
std::map<std::string, int> ages = {{"Аня", 21}, {"Борис", 35}};
std::vector<Student> group = {{"Аня", 95}, {"Борис", 70}};
```

В отладчике это выглядит так:

```
v      = std::vector of length 3, capacity 3 = {10, 20, 30}
ages   = std::map with 2 elements = {["Аня"] = 21, ["Борис"] = 35}
group  = std::vector of length 2, capacity 2 = {{name = "Аня", score = 95},
                                                {name = "Борис", score = 70}}
```

Не внутренности и не адреса, а именно содержимое — вместе с русскими буквами. Структуры внутри вектора тоже разворачиваются по полям.

#### Стек вызовов — «как я сюда попал»

Панель **Call Stack** показывает цепочку вызовов сверху вниз: текущая функция, кто её вызвал, кто вызвал того. Если программа упала где-то в глубине, стек отвечает на главный вопрос — из какого места твоего кода туда пришли.

```
normalize (word="the") at text.cpp:20      ← сейчас мы здесь
main () at text.cpp:50                     ← отсюда вызвали
```

Щёлкни по строке `main` — редактор перепрыгнет туда, и Variables покажет переменные уже той функции.

#### Watch — следить за одним выражением

Панель **Watch** — это список выражений, которые пересчитываются на каждом шаге. Удобно, когда нужно не всё подряд, а одно: добавь туда `sum`, `i < v.size()` или `v.size()` и наблюдай, как значение меняется от строки к строке.

#### Что отладчик не умеет

В консоли отладчика (**Debug Console**) можно печатать выражения, но **обращение по индексу там не работает**:

```
print v          ✅ покажет весь вектор
print s          ✅ покажет строку целиком
print v[1]       ❌ Could not find operator[]
```

Это ограничение gdb, а не твоя ошибка. Обходится просто: разверни контейнер в панели Variables — там элементы разложены по индексам и щёлкаются мышкой.

#### Когда отладчик не нужен

Не всё стоит отлаживать пошагово. Если ошибка в одной формуле, быстрее посмотреть на неё глазами. Отладчик выигрывает, когда:

- программа делает не то, а где именно — непонятно;
- значение переменной берётся «ниоткуда»;
- цикл крутится не столько раз, сколько ждёшь;
- программа падает, и надо увидеть стек вызовов.

А `std::cout` остаётся хорош, когда нужно проследить **историю**: как менялось значение за все двести витков цикла. Отладчик показывает один момент, печать — весь путь.

### Кракозябры вместо русского

- в коде — `SetConsoleCP(CP_UTF8)` и `SetConsoleOutputCP(CP_UTF8)`, как выше;
- разово в терминале — `chcp 65001`;
- файл должен быть сохранён в UTF-8 (правый нижний угол VS Code);
- шрифт консоли — Consolas или Cascadia Mono.

### `windows.h` занимает часть имён — и ошибка выглядит дико

`#include <windows.h>` нужен ради русских букв, но вместе с ним в программу попадают тысячи имён и макросов Windows. Если назвать свою переменную так же, ошибка будет совершенно не про то, что ты сделал:

```cpp
#include <windows.h>
#include <iostream>

int main() {
  int ERROR = 5;              // ❌ error: expected unqualified-id before numeric constant
  std::cout << ERROR;         //    компилятор ругается на строку, где всё «правильно»
}
```

Причина в том, что `ERROR` — уже макрос Windows, и препроцессор подменил его числом ещё до компиляции. Получилось `int 0 = 5;`.

Проверено на твоей сборке — вот имена, которые занимать нельзя:

| Нельзя | Чем заменить |
|---|---|
| `ERROR` | `errorCode`, `errorText` |
| `IN`, `OUT` | `input`, `output` |
| `DELETE` | `toDelete`, `removeItem` |
| `TRUE`, `FALSE` | обычные `true` / `false` |
| `NULL` | `nullptr` |
| `near`, `far` | `nearPoint`, `farPoint` |
| `interface` | `iface` |
| `SIZE`, `POINT`, `RECT` (в глобальной области) | `BOARD_SIZE`, `Point2D`, `Rect2D` |

Правило простое: **имена из ЗАГЛАВНЫХ букв — территория Windows.** Пиши константы как `BOARD_SIZE`, `MAX_ATTEMPTS`, `CM_PER_INCH` — из двух слов, и не столкнёшься.

> Если ошибка совсем не сходится со строкой, на которую показывает компилятор, — проверь, не занял ли `windows.h` твоё имя. Это первое, что стоит подозревать при загадочном `expected unqualified-id`.

## 2. Типы данных

| Тип | Размер | Диапазон | Когда брать |
|---|---|---|---|
| `bool` | 1 байт | `true` / `false` | флаги, результаты сравнений |
| `char` | 1 байт | один символ | **символы, не числа!** |
| `int` | 4 байта | ±2 147 483 647 | **по умолчанию для всех целых** |
| `long long` | 8 байт | ±9 · 10¹⁸ | суммы, произведения, факториалы |
| `float` | 4 байта | ~7 значащих цифр | почти никогда |
| `double` | 8 байт | ~15 значащих цифр | **по умолчанию для дробных** |
| `std::string` | — | текст любой длины | всегда вместо `char[]` |

**Правило по умолчанию: `int` для целых, `double` для дробных, `std::string` для текста.**
Оптимизировать типы будешь потом, когда появится причина.

```cpp
#include <climits>              // пределы целых типов
#include <iostream>

std::cout << INT_MAX << "\n";   // → 2147483647  — максимум для int
std::cout << INT_MIN << "\n";   // → -2147483648 — минимум
std::cout << LLONG_MAX << "\n"; // → 9223372036854775807 — максимум для long long
```

### Ловушка 1: `char` — это символ, а не число

```cpp
char c = 0;
std::cin >> c;                  // пользователь ввёл: 5

std::cout << c << "\n";         // → 5    выглядит как число...
std::cout << c + 0 << "\n";     // → 53   ...но внутри лежит КОД символа '5'

int digit = c - '0';            // '5'(53) - '0'(48) = 5 — вот теперь настоящее число
std::cout << digit * 2 << "\n"; // → 10
```

Почему `- '0'` работает: цифры в таблице символов идут подряд, `'0'`=48, `'1'`=49 … `'9'`=57. Вычитая код нуля, получаешь порядковый номер цифры.

**Где это нужно по-настоящему** — разбор числа, введённого как строка:

```cpp
std::string s = "2026";
int sum = 0;
for (char ch : s)               // проходим по символам строки
  sum += ch - '0';              // каждый превращаем в цифру и копим
std::cout << sum << "\n";       // → 10   (2+0+2+6)
```

### Ловушка 2: `unsigned` и пользовательский ввод

```cpp
unsigned int n = 0;             // unsigned = «только неотрицательные»
std::cin >> n;                  // пользователь ввёл: -5

std::cout << n << "\n";         // → 4294967291  минус превратился в огромное число
if (n >= 0)                     // ❌ это условие ИСТИННО всегда: unsigned не бывает < 0
  std::cout << "число неотрицательное\n";   // напечатается даже для -5
```

**Правило:** читай в `int`, проверяй руками, конвертируй только потом.

```cpp
int n = 0;
std::cin >> n;
if (n < 0) {                                  // ✅ вот эта проверка работает
  std::cout << "Нужно неотрицательное число\n";
  return 1;
}
unsigned int count = static_cast<unsigned int>(n);   // теперь конвертировать безопасно
```

### Ловушка 3: `int` переполняется молча

```cpp
int n = 100000;
int sq = n * n;                 // ❌ 10 000 000 000 в int не влезает
std::cout << sq << "\n";        // → 1410065408  мусор, и никакой ошибки

long long sqOk = 1LL * n * n;   // ✅ 1LL делает первый множитель long long,
std::cout << sqOk << "\n";      //    и всё выражение считается в long long
                                // → 10000000000
```

Ещё две ситуации, где это ловится постоянно:

```cpp
int n = 100000;

// Сумма 1..n
int bad = n * (n + 1) / 2;              // ❌ n*(n+1) переполнится ДО деления
long long good = 1LL * n * (n + 1) / 2; // ✅
std::cout << good << "\n";              // → 5000050000

// Факториал
long long fact = 1;                     // ✅ сразу long long
for (int i = 1; i <= 20; ++i)
  fact *= i;                            // 20! ещё влезает, 21! уже нет
std::cout << fact << "\n";              // → 2432902008176640000
```

> **Правило:** если в выражении есть умножение и числа могут быть большими — начинай с `1LL *`. Стоит это ноль, а спасает от бага, который не виден глазами.

### Целочисленное деление и остаток

Деление двух **целых** даёт целое: дробная часть просто отбрасывается — это **не округление**.

```cpp
#include <iostream>

int main() {
  int a = 7;
  int b = 2;
  std::cout << a / b << "\n";     // → 3    дробная часть отброшена (не 3.5 и не 4)
  std::cout << a % b << "\n";     // → 1    % — остаток от деления
  std::cout << 7.0 / 2 << "\n";   // → 3.5  хотя бы одно число дробное — деление дробное
  return 0;
}
```

Отсюда классическая ошибка «получил 0 вместо дроби»: если оба операнда целые, дробь теряется **до** того, как результат попадёт в `double`.

```cpp
int scored = 3;
int total = 4;
double ratio = scored / total;                 // ❌ 3/4 = 0 (целые!) → 0.0
double ok = static_cast<double>(scored) / total; // ✅ 0.75 — привели к double до деления
```

Остаток `%` — рабочая лошадка. Два приёма, которые встретишь постоянно (в том числе в геймдеве):

```cpp
bool even = (n % 2 == 0);         // чётное? остаток от деления на 2 равен нулю
int next = (i + 1) % size;        // идти по кругу: после последнего индекса снова 0
```

Две ловушки:

- **Деление на ноль** для целых — не ошибка компиляции, а падение программы во время работы. Проверяй делитель заранее: `if (b != 0) ...`.
- **Знак остатка** идёт за делимым: `-7 % 3` даёт `-1`, а не `2`. Для «индекса по кругу» с возможными отрицательными числами это важно — приводи к неотрицательному отдельно.

### Ловушка 4: дробные числа и точность

`double` хранит число в двоичной дроби, а в двоичной дроби `0.1` записать точно нельзя — как `1/3` не записать точно в десятичной. Поэтому дробные **нельзя сравнивать через `==`**:

```cpp
#include <iostream>
#include <cmath>

int main() {
  double a = 0.1 + 0.2;
  std::cout << (a == 0.3) << "\n";          // → 0   ЛОЖЬ, хотя ждём 0.3
  std::cout << std::abs(a - 0.3) << "\n";   // → 5.55112e-17  крохотная разница, не ноль

  const double EPS = 1e-9;                  // допустимая погрешность
  if (std::abs(a - 0.3) < EPS)              // ✅ сравниваем «почти равны»
    std::cout << "равны с точностью до EPS\n";
  return 0;
}
```

Компилятор об этом **не предупреждает** (`==` для `double` разрешён), поэтому лови такое сам.

**Правила на каждый день:**

- сравнивай дробные через «разница меньше `EPS`», а не `==`;
- деньги и всё, где важна точная копейка, считай в **целых** (в копейках/центах), а не в `double`;
- на экран выводи с нужным числом знаков — `std::format("{:.2f}", x)` (см. [Ввод и вывод](02-vvod-vyvod.md)), внутри при этом храни полное значение.

### `std::size_t` — почему компилятор ругается на `v.size()`

```cpp
std::vector<int> v = {10, 20, 30};

for (int i = 0; i < v.size(); ++i)     // ❌ warning: comparison of integer
  std::cout << v[i];                   //    expressions of different signedness
```

`v.size()` возвращает **`std::size_t`** — беззнаковое целое (отрицательного размера не бывает). Сравнивать его с `int` компилятор считает подозрительным, и он прав: в спорной ситуации `int` молча превращается в огромное положительное число.

Три честных выхода:

```cpp
// 1. Тот же тип с обеих сторон
for (std::size_t i = 0; i < v.size(); ++i)
  std::cout << v[i] << " ";                  // → 10 20 30

// 2. Лучше: индекс вообще не нужен
for (int value : v)
  std::cout << value << " ";                 // → 10 20 30

// 3. Если int нужен именно как число — явное преобразование
int count = static_cast<int>(v.size());
std::cout << "Элементов: " << count << "\n"; // → Элементов: 3
```

Почему это не занудство — вот реальный баг, который ловит этот флаг:

```cpp
std::vector<int> v;                    // ПУСТОЙ вектор

for (std::size_t i = 0; i < v.size() - 1; ++i)   // ❌ 0 - 1 в size_t = 18446744073709551615
  std::cout << v[i];                             //    цикл уходит в бесконечность и портит память

for (std::size_t i = 0; i + 1 < v.size(); ++i)   // ✅ переносим -1 в другую часть
  std::cout << v[i];                             //    для пустого вектора просто не выполнится
```

### Среднее: почему `static_cast` нужен с обеих сторон

Самая частая формула в учебных задачах — среднее. И у неё есть тихая ловушка именно с твоими флагами (`-Wconversion` включён в `settings.json`).

```cpp
std::vector<int> v = {1, 2, 3, 4};
int sum = 10;

double avg = sum / v.size();                              // ❌ целочисленное деление → 2
double avg = static_cast<double>(sum) / v.size();         // ⚠️ считает верно (2.5), НО:
// warning: conversion from 'size_type' {aka 'long long unsigned int'}
//          to 'double' may change value [-Wconversion]

double avg = static_cast<double>(sum)                     // ✅ так предупреждения нет
           / static_cast<double>(v.size());
```

Почему компилятор придирается ко второй строке, хотя ответ верный: `size()` возвращает 64-битное целое, а `double` хранит примерно 15 значащих цифр. Для огромных значений преобразование теряет точность — и компилятор честно предупреждает о такой **возможности**, хотя на твоих размерах данных этого никогда не случится.

Вывод простой: **приводи к `double` обе части**, и чеклист «предупреждений ноль» останется выполнимым. Формула становится длиннее, поэтому её удобно один раз спрятать в функцию:

```cpp
double average(const std::vector<int> &v) {
  if (v.empty())                                  // защита: деления на ноль не будет
    return 0.0;
  int sum = 0;
  for (int x : v)
    sum += x;
  return static_cast<double>(sum) / static_cast<double>(v.size());
}

std::cout << average({1, 2, 3, 4});               // → 2.5
std::cout << average({});                         // → 0    и никакого nan
```

### Литералы: разделитель разрядов и суффиксы

Число прямо в коде называется **литералом**. У литералов есть удобные мелочи, которые делают код читаемее и убирают ошибки типа.

```cpp
#include <iostream>

int main() {
  int million = 1'000'000;          // апостроф — разделитель разрядов: читать легче, на смысл не влияет
  long long big = 5'000'000'000LL;  // суффикс LL — литерал типа long long (в int такое число не влезет)
  double half = 0.5;                // дробный литерал по умолчанию double
  unsigned u = 10u;                 // суффикс u — беззнаковый литерал
  int hex = 0xFF;                   // 0x… — шестнадцатеричная запись: 255
  int bin = 0b1010;                 // 0b… — двоичная запись: 10
  std::cout << million << " " << big << " " << half << " "
            << u << " " << hex << " " << bin << "\n";
  return 0;
}
```

| Запись | Что значит |
|---|---|
| `1'000'000` | разделитель разрядов `'` (только для глаз, C++14+) |
| `100LL` | тип `long long` — чтобы большое произведение не переполнило `int` (см. [ловушку 3](#ловушка-3-int-переполняется-молча)) |
| `10u` | беззнаковый (`unsigned`) |
| `3.14f` | `float` вместо `double` (нужно редко) |
| `0xFF`, `0b1010` | шестнадцатеричная и двоичная запись — удобно для флагов и масок |

## 3. Переменные и константы

```cpp
int x = 5;                        // объявление + инициализация в одной строке
const double CM_PER_INCH = 2.54;  // const = «менять нельзя», компилятор проследит
auto y = 3.14;                    // auto = «выведи тип сам» → здесь double
```

### Переменная без начального значения содержит мусор

```cpp
int count;                       // ❌ не ноль! Внутри случайное число из памяти
count++;                         //    прибавили 1 к мусору — получили другой мусор
std::cout << count;              // → 32764, или -1073741248, или что угодно

int total = 0;                   // ✅ всегда задавай начальное значение
total++;
std::cout << total;              // → 1
```

Коварство в том, что мусор **иногда** случайно равен нулю, и программа «работает». Потом ты меняешь соседнюю строку — и она ломается без видимой причины.

### Инициализация в фигурных скобках ловит сужение

Инициализировать можно через `=` или через фигурные скобки `{}`. Разница не косметическая: `{}` **запрещает молчаливую потерю данных** (сужение типа) — компилятор остановит тебя ещё до запуска.

```cpp
int a = 3.14;    // ⚠️ молча станет 3; с флагом -Wconversion будет предупреждение
int b{3.14};     // ❌ error: narrowing conversion — {} не даёт потерять дробь
int c{};         // ✅ пустые {} инициализируют нулём — надёжно и коротко
```

Поэтому привычка «инициализирую через `{}`» бесплатно закрывает целый класс ошибок и заодно решает проблему мусора из прошлого раздела:

```cpp
#include <iostream>
#include <vector>

int main() {
  int count{};                    // 0 — пустые {} всегда дают ноль нужного типа
  double ratio{};                 // 0.0
  std::vector<int> scores{10, 20, 30};   // {} заодно заполняет контейнер
  std::cout << count << " " << ratio << " " << scores.size() << "\n"; // → 0 0 3
  return 0;
}
```

> Одно исключение стоит знать заранее: `std::vector<int> v(5)` (круглые скобки) — это «пять нулей», а `std::vector<int> v{5}` (фигурные) — это «один элемент, равный 5». Подробнее — в разделе про [контейнеры](06-konteynery.md).

### `const` — не формальность

```cpp
const double PI = 3.14159;
const int MAX_ATTEMPTS = 3;

PI = 3.14;                       // ❌ error: assignment of read-only variable 'PI'
                                 //    компилятор поймает это ещё до запуска
```

Три причины писать `const`:

```cpp
// 1. Защита от случайного изменения
const int SIZE = 10;

// 2. Читателю сразу понятно, что значение постоянно
const double TAX_RATE = 0.13;

// 3. Число получает имя — код объясняет сам себя
double tax = income * 0.13;        // ❌ что за 0.13? через месяц не вспомнишь
double tax = income * TAX_RATE;    // ✅ понятно без комментариев
```

### `constexpr`: константа времени компиляции

`const` означает «после инициализации не меняется». `constexpr` — строже: «значение известно **уже на этапе компиляции**». Разница видна там, где число обязано быть известно до запуска — например, размер массива фиксированной длины.

```cpp
#include <array>
#include <iostream>

int main() {
  constexpr int BOARD_SIZE = 8;            // известно компилятору, а не только «не меняется»
  std::array<int, BOARD_SIZE> row{};       // размер std::array — только компайл-тайм-константа
  std::cout << row.size() << "\n";         // → 8
  return 0;
}
```

Практическое правило на этом этапе: **если значение можно посчитать до запуска — пиши `constexpr`** (размеры, математические константы, пределы). Если значение приходит во время работы (из ввода, из файла) — это обычная переменная или `const`, но не `constexpr`.

```cpp
constexpr double PI = 3.141592653589793;   // ✅ известно всегда
constexpr int MAX_PLAYERS = 4;             // ✅ размер под массив игроков

int n = 0;
std::cin >> n;
const int size = n;                        // ✅ const: не меняется, но известно лишь в рантайме
// constexpr int size = n;                 // ❌ error: n — не константа времени компиляции
```

### Когда уместен `auto`

```cpp
// ✅ Тип длинный и не несёт смысла
auto it = ages.find("Аня");                     // вместо std::map<std::string,int>::iterator
auto evens = std::count_if(v.begin(), v.end(), isEven);   // возвращает не int, а ptrdiff_t

// ❌ Тип короткий и важен для понимания
auto n = readInt("N: ");         // что это? число? строка? приходится идти читать функцию
int n = readInt("N: ");          // ✅ видно сразу

// ⚠️ Осторожно: auto копирует
auto s = veryLongString;         // копия всей строки
const auto &s = veryLongString;  // ✅ ссылка, без копии
```

### Область видимости

Переменная живёт до закрывающей фигурной скобки своего блока:

```cpp
int main() {
  int outer = 1;                 // живёт до конца main

  {                              // начало вложенного блока
    int inner = 2;               // живёт только внутри этих скобок
    std::cout << outer + inner;  // → 3   отсюда видно обе
  }                              // здесь inner уничтожается

  std::cout << inner;            // ❌ error: 'inner' was not declared in this scope
}
```

Та же история с циклом — и это частая ошибка:

```cpp
for (int i = 0; i < 10; ++i) {
  int found = i * 2;             // создаётся заново на каждом витке
}
std::cout << i;                  // ❌ i не существует за пределами цикла
std::cout << found;              // ❌ и found тоже

int result = 0;                  // ✅ если значение нужно после цикла —
for (int i = 0; i < 10; ++i)     //    объявляй ДО него
  result += i;
std::cout << result;             // → 45
```

### Имена

```cpp
const double CM_PER_INCH = 2.54;   // константы — БОЛЬШИМИ_БУКВАМИ
int studentCount = 0;              // переменные — camelCase
double averageScore = 0.0;         // или snake_case: average_score
bool isValid = true;               // bool удобно называть с is/has — читается как вопрос

```

Главное — **одинаково во всём файле**. Имя должно объяснять смысл: `dum` не объясняет ничего, `d` тоже, а `daysInMonth` — объясняет.
