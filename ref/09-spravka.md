| `<array>` | `std::array` — массив фиксированного размера |

| `<algorithm>` | `sort`, `find`, `count_if`, `max_element`, `reverse`, `remove_if`, `clamp` |
| `<numeric>` | `accumulate`, `gcd`, `lcm` |

| `<format>` | `std::format` — форматирование строк (C++20) |
| `<cmath>` | `sqrt`, `pow`, `abs` для дробных, `round`, `floor`, `ceil`, `isnan`, `isinf` |
| `<cstdlib>` | `abs` для целых, `rand` |
| `<cctype>` | `toupper`, `tolower`, `isdigit`, `isalpha` |
| `<limits>` | `numeric_limits` — нужен для `cin.ignore` |
| `<iomanip>` | `setprecision`, `setw`, `fixed` |
| `<climits>` | `INT_MAX`, `INT_MIN`, `LLONG_MAX` |
| `<fstream>` | `ifstream`, `ofstream` |
| `<sstream>` | `istringstream` — разбор строки как потока |
| `<queue>` / `<stack>` / `<deque>` | очередь (FIFO), стек (LIFO), двусторонняя очередь |
| `<random>` | нормальные случайные числа, `std::shuffle` берёт генератор отсюда |
| `<cassert>` | `assert` — проверка «невозможного» при отладке |
| `<cstddef>` | `std::size_t` |
| `<windows.h>` | `SetConsoleCP` — только Windows |

**Не пиши `#include <bits/stdc++.h>`** — это нестандартное расширение GCC: замедляет сборку, не соберётся у половины людей и прячет от тебя, что откуда берётся.

Забыл заголовок — компилятор скажет прямо:

```
error: 'sort' is not a member of 'std'
note: 'std::sort' is defined in header '<algorithm>'
```

## 24. Устаревшее: что встретишь в учебниках и чем это заменить

Большинство книг и видео по C++ написаны до 2011 года или переписаны с них. Язык с тех пор изменился сильно. Ниже — то, что ты почти наверняка увидишь, и то, чем это заменяется сегодня.

**Читать старый код надо уметь** — его вокруг много. Писать так самому не надо.

| Встретишь | Пиши вместо этого | Почему |
|---|---|---|
| `using namespace std;` | `std::` перед именами | см. разбор ниже |
| `#include <bits/stdc++.h>` | конкретные заголовки | нестандартно, есть только в GCC |
| `void main()` | `int main()` | твой g++ прямо откажет: `error: '::main' must return 'int'` |
| `char name[50]; strcpy(...)` | `std::string` | длина не проверяется — источник ошибок |
| `int *a = new int[n]; ... delete[] a;` | `std::vector<int> a(n);` | забытый `delete` = утечка памяти |
| `NULL` | `nullptr` | `NULL` — это просто `0`, путается с числом |
| `printf("%d", x)` / `scanf` | `std::cout` / `std::cin` | не проверяют типы: `%d` для `double` = мусор |
| `#define SIZE 10` | `const int SIZE = 10;` | `#define` не знает типов и области видимости |
| `(int)x` | `static_cast<int>(x)` | C-style cast молча делает **любое** преобразование |
| `rand() % 6` | `<random>` | распределение неравномерное |
| `typedef long long ll;` | `using ll = long long;` | `using` читается слева направо |
| `system("pause")` | `std::cin.get()` | запускает внешнюю программу, работает не везде |
| `#include <conio.h>`, `getch()` | обычный ввод | заголовок только для старых Windows-компиляторов |
| `std::endl` в цикле | `"\n"` | `endl` сбрасывает буфер на каждой строке |
| `gets(buf)` | `std::getline` | **удалён из стандарта** в C++14 как небезопасный; g++ на него ругается |

### `using namespace std;` — почему в этом справочнике его нет

Самое частое, что видишь в учебниках, — и первое, от чего отказываются на практике.

```cpp
using namespace std;      // «разреши не писать std::»

cout << "Привет";         // работает
string s = "текст";       // тоже
```

Проблема в том, что эта строка втаскивает **все** имена из `std` разом, а их тысячи. Некоторые из них — обычные слова:

```cpp
using namespace std;

int count = 0;            // ❌ конфликтует с std::count из <algorithm>
double distance = 5.0;    // ❌ и с std::distance
int size = 10;            // ❌ и с std::size
```

Ошибка при этом получается не там, где ты её сделал, а в глубине шаблонов — на пол-экрана текста про то, чего ты не писал.

```cpp
std::cout << "Привет";    // ✅ пять лишних символов, зато видно, откуда имя
```

Ещё одна выгода `std::`: сразу понятно, что своё, а что из стандартной библиотеки. `sort(v.begin(), v.end())` — чья это `sort`, твоя или библиотечная? С `std::sort` вопроса не возникает.

> Если писать `std::` совсем невмоготу, есть компромисс — втащить **по одному имени**, а не всё сразу: `using std::cout;`. Но внутри заголовочных файлов (`.h`) `using namespace` не пишут никогда: он расползётся по всем файлам, которые их подключат.

### `new` / `delete` — самая опасная привычка из старых книг

```cpp
// ❌ Как учат в старых книгах
int n = 10;
int *arr = new int[n];        // выделили память вручную
for (int i = 0; i < n; ++i)
  arr[i] = i;
// ... сто строк кода ...
delete[] arr;                 // ⚠️ забудешь — утечка. Ошибёшься с [] — порча памяти.
                              //    Выйдешь по return раньше — тоже утечка
```

```cpp
// ✅ Как пишут сейчас
std::vector<int> arr(n);      // память выделится сама
for (int i = 0; i < n; ++i)
  arr[i] = i;
// освободится сама при выходе из области видимости — забыть невозможно
```

`vector` делает ровно то же самое, но освобождение памяти привязано к времени жизни переменной. Это и есть **RAII** — та же идея, по которой сами закрываются файлы ([раздел 21](08-struct-fayly.md#21-файлы)).

Пока ты решаешь учебные задачи, `new` не нужен **вообще**. Когда встретишь его в чужом коде — знай, что современная замена почти всегда `vector`, `string` или (позже) `std::unique_ptr`.

### `printf` — почему потоки надёжнее

```cpp
double x = 3.14;

printf("%d\n", x);         // ❌ соврали про тип: напечатается мусор
std::cout << x << "\n";    // ✅ тип определяется сам, соврать нечем
```

Здесь GCC заступится — при включённом `-Wall` он сверяет строку формата с аргументами:

```
warning: format '%d' expects argument of type 'int', but argument 2 has type 'double'
```

Но проверка держится на том, что формат — литерал прямо в вызове. Стоит собрать строку формата в переменной или взять её из файла, и сверять станет нечего: `printf` просто поверит на слово и напечатает мусор. Собери без `-Wall` — и предупреждения не будет вовсе.

`printf` короче в форматировании — за это его любят на олимпиадах. Но `std::format` ([раздел 4](02-vvod-vyvod.md#4-ввод-и-вывод)) даёт ту же краткость **и** проверку типов, причём на этапе компиляции — там соврать нельзя даже нарочно.

### C-style cast — почему `static_cast` длиннее не зря

```cpp
double d = 3.99;

int a = (int)d;                    // ❌ старая запись: 3
int b = static_cast<int>(d);       // ✅ современная: 3, и это то же самое
```

Разница видна на другом примере:

```cpp
const std::string s = "текст";

char *p = (char *)&s;              // ❌ скомпилируется! C-style cast снял const
                                   //    и сменил тип — молча, без единого предупреждения
char *q = static_cast<char *>(&s); // ✅ error — компилятор не даст это сделать
```

`static_cast` умеет только осмысленные преобразования и откажется от подозрительных. Плюс его легко найти поиском по коду, а `(int)` теряется среди обычных скобок.

### Что из старого учить всё-таки стоит

Не всё старое — плохое. Это просто **другой уровень**, и он ниже:

- **`char` и коды символов** — нужны для разбора строк ([раздел 2](01-osnovy.md#2-типы-данных)), никуда не делись;
- **обычные массивы `int a[10]`** — нужно узнавать в чужом коде и понимать, чем плохи;
- **указатели `*` и `&`** — без них не понять, как устроены `vector` и ссылки внутри;
- **`printf`** — пригодится, если возьмёшься за C.

Разница в подходе: это стоит **уметь читать**, но выбирать первым инструментом — нет.

## 25. Чеклист перед сдачей

Пробегись глазами, это 60 секунд:

- [ ] Собрал с `-Wall -Wextra`, предупреждений **ноль**
- [ ] Каждая переменная получает значение **при объявлении**
- [ ] Ввод чисел идёт через `readInt`, а не через голый `cin >>`
- [ ] Ни одного `unsigned` для пользовательского ввода
- [ ] После каждого сообщения об ошибке стоит `return`
- [ ] Проверил на: букве, пустой строке, `0`, `-5`, `2000000000`, границах диапазона
- [ ] Деления целых там, где ждёшь дробь, нет (`1.0 *` или `static_cast<double>`)
- [ ] Перед каждым делением делитель проверен на ноль, перед средним — контейнер на пустоту
- [ ] Умножения больших чисел защищены `1LL *`
- [ ] Обращений к `v[i]`, где `i` может быть `>= size()`, нет
- [ ] Нет `using namespace std;`, нет `new` / `delete`, нет `#include <bits/stdc++.h>`
- [ ] Заголовки функций не скопированы друг у друга
- [ ] Одна и та же формула не написана дважды
- [ ] У каждого `cin` есть приглашение: пользователю понятно, чего от него хотят

### Симптом → причина

| Симптом | Причина | Раздел |
|---|---|---|
| После неверного ввода всё сломалось | сломанный `cin`, нет `clear()` + `ignore()` | 4 |
| `getline` возвращает пустоту | остался Enter от `>>` | 4 |
| Проверка `n >= 0` не срабатывает | `unsigned` вместо `int` | 2 |
| Ввёл `5`, получил `53` | `char` вместо `int` | 2 |
| Большие числа дают минус | переполнение `int`, нужен `1LL *` | 2 |
| `7 / 2` даёт `3` | целочисленное деление | 5 |
| Средний балл всегда целый | то же самое, нужен `static_cast<double>` | 5 |
| `0.1 + 0.2 != 0.3` | сравнение `double` через `==` | 5 |
| Условие всегда истинно | `=` вместо `==`, или `1 < x < 10` | 6 |
| Программа падает на делении | деление на ноль, нет проверки `d != 0` | 5 |
| `switch` печатает лишнее | забыт `break` | 7 |
| Цикл выполняется на раз больше | `<=` вместо `<` | 8 |
| Цикл не выполняется вообще | `while (n > 0)` для отрицательного `n` | 8 |
| Бесконечный цикл | условие не меняется внутри тела | 8 |
| Изменения в цикле не сохраняются | `for (auto x : v)` вместо `for (auto &x : v)` | 8 |
| Программа портит данные, но не падает | выход за границы, нужен `.at()` | 11 |
| В словаре появились лишние ключи | читал через `m[key]` | 12 |
| Порядок вывода каждый раз разный | это `unordered_map` | 13 |
| Ошибка на пол-экрана про `operator<` | свой `struct` как ключ `map` | 12 |
| `cout << max_element(...)` печатает мусор | забыл `*` | 17 |
| Предупреждение про signedness | `int i` против `v.size()` | 2 |
| Всё тормозит на больших данных | range-for копирует, нужен `const auto &` | 8 |
| Сумма отрицательная или бессмысленная | `accumulate(..., 0)` вместо `0LL` | 18 |
| Программа печатает `nan` или `inf` | делили на ноль в `double`, нет проверки на пустоту | 5 |
| `if (avg > 0)` и `if (avg <= 0)` оба ложны | это `nan`, проверять надо через `std::isnan` | 5 |
| Таблица с русскими именами разъехалась | `setw` считает байты; нужен `std::format` | 4 |
| Все числа вдруг с двумя знаками после точки | `setprecision` действует до отмены | 4 |
| `v[5]` не ругается, но данные портятся | нет флага `-D_GLIBCXX_ASSERTIONS` | 1 |
| `-fsanitize=address` не линкуется | на MinGW не поддерживается, это не твоя ошибка | 1 |
| Ошибка на пол-экрана про шаблоны в простом коде | `using namespace std;` плюс своя переменная `count`/`size`/`distance` | 24 |
| `int x{3.14}` не компилируется | это сужение; фигурные скобки защищают — напиши преобразование явно | 3 |
| «Случайное» одинаково при каждом запуске | генератор пересоздаётся; создавай `mt19937` один раз | 20 |

### Как проверять свою программу

**Ломай её специально.** После «заработало» прогони шесть вводов:

| Ввод | Что проверяет |
|---|---|
| `abc` | защиту от нечислового ввода |
| пустой Enter | не зависнет ли, не примет ли мусор |
| `0` | деление на ноль, пустые списки |
| `-5` | отрицательные, `unsigned`, `while (n > 0)` |
| `2000000000` | переполнение при умножении |
| границы диапазона | `<` против `<=` (если ждёшь 1–8, дай 0, 1, 8, 9) |

Большинство багов ловится этим списком, а не перечитыванием кода.

**Если не сходится — четыре шага перед тем, как спрашивать:**

1. Прочитал сообщение компилятора целиком? **Первую** ошибку, не последнюю.
2. Поставил точку останова `F9` и посмотрел значения в панели Variables?
3. Вывел промежуточные значения? `std::cout << "dx = " << dx << "\n";` — грубо, но работает.
4. Проверил на самом простом входе? Не на `12345`, а на `5`.

Бери их, когда основной справочник (1–21) уже освоен.

Не гонись за списком. Каждый пункт стоит того, чтобы написать по нему три маленькие программы, — иначе он не запомнится.

**Где смотреть правду:** [cppreference.com](https://en.cppreference.com/) — не учебник, а справочник. Сначала непривычно, потом окажется, что там есть ответ на любой вопрос.

**Как спрашивать, чтобы учиться:** показывай свой код и проси объяснить причину, а не прислать готовый ответ. «Вот моя функция и вход, на котором она врёт — скажи, на каком шаге ломается логика, не переписывай.» Иначе научится тот, кто отвечает.
