# Тема 9. Ловим баги

Здесь программы уже написаны, но **работают неправильно**. Задача — найти ошибку,
объяснить её себе и исправить. Это самый полезный навык: чужой (и свой) код чаще
приходится чинить, чем писать с нуля. Каждая ошибка тут — представитель целого класса
багов, которые вы будете узнавать в лицо всю дальнейшую практику.

> 📖 **Опирается на разделы 11–12 справочника** ([11-oshibki](../ref/11-oshibki.md) и [12-lovim-bagi](../ref/12-lovim-bagi.md)).
> Там метод поиска багов и разбор частых сообщений компилятора.

## Чему вы здесь научитесь

- Узнавать в лицо классические баги: целочисленное деление, `=` вместо `==`, выход за
  границу массива, неверная инициализация, забытый `break`.
- Видеть тонкие ошибки: цикл `while (!eof())`, читающий на один раз больше, и беззнаковое
  переполнение (`size() - 1` на пустом контейнере).
- Не «чинить наугад», а сначала **понять**, почему ломается, и проверить гипотезу на минимальном входе.

## Метод: как искать баг (а не гадать)

1. **Прочитайте, что программа должна делать**, и найдите вход, на котором она врёт.
2. **Сформулируйте гипотезу**: «мне кажется, дело вот в этой строке, потому что…».
3. **Проверьте гипотезу**: поставьте точку останова (`F9`) и посмотрите значения в панели Variables либо выведите промежуточное `std::cout << "x = " << x << "\n";`.
4. **Почините и перепроверьте** — на том же входе, где ломалось, и на паре соседних.

Не переписывайте программу целиком — найдите **одну** строку-виновника. Умение сузить
проблему до одной строки важнее, чем умение написать заново.

**Как работать с блоком:** сначала честно найдите баг сами (по 10–15 минут на задачу),
запишите свою гипотезу, и только потом открывайте подсказку — сверить.

## 9.1. Среднее двух чисел 🟢

Программа должна печатать среднее арифметическое двух целых чисел, но для `3` и `4`
печатает `3` вместо `3.5`.

```cpp
#include <iostream>

int main() {
  int a, b;
  std::cin >> a >> b;
  double avg = (a + b) / 2;
  std::cout << avg << "\n";
}
```

**Пример:** ввод `3 4` — ожидается `3.5`.

**Класс бага:** целочисленное деление. Результат посчитан в `int` **до** того, как попал в `double`.
**Где кусается:** средний балл, средняя цена, проценты — везде, где ждёте дробь, а получаете целое.

## 9.2. Ноль или нет 🟢

Программа должна печатать `ZERO`, если ввели ноль, и `NOT ZERO` иначе. Но она
**всегда** печатает `NOT ZERO`, даже на вводе `0`.

```cpp
#include <iostream>

int main() {
  int x;
  std::cin >> x;
  if (x = 0) {
    std::cout << "ZERO\n";
  } else {
    std::cout << "NOT ZERO\n";
  }
}
```

**Пример:** ввод `0` — ожидается `ZERO`.

**Класс бага:** `=` (присваивание) вместо `==` (сравнение) — одна из самых частых опечаток.
**Где кусается:** любое условие. Компилятор с `-Wall` обычно предупреждает — научитесь читать это предупреждение.

## 9.3. Сумма массива 🟡

Программа читает `N` чисел и должна печатать их сумму. Вместо этого она то падает, то
печатает мусор (лишнее «случайное» слагаемое).

```cpp
#include <iostream>
#include <vector>

int main() {
  int n;
  std::cin >> n;
  std::vector<int> v(n);
  for (int i = 0; i < n; ++i) {
    std::cin >> v[i];
  }
  long long sum = 0;
  for (int i = 0; i <= n; ++i) {
    sum += v[i];
  }
  std::cout << sum << "\n";
}
```

**Пример:** ввод `3` и `1 2 3` — ожидается `6`.

**Класс бага:** ошибка «на единицу» (off-by-one) — выход за границу массива.
**Где кусается:** любой цикл по массиву/строке; `<=` вместо `<` — классика. С флагом `-D_GLIBCXX_ASSERTIONS` такой выход ловится сразу.

## 9.4. Максимум 🟡

Программа должна печатать наибольшее из введённых чисел (числа читаются до конца ввода).
На вводе из одних отрицательных чисел она ошибается и печатает `0`.

```cpp
#include <iostream>

int main() {
  int x;
  int best = 0;
  while (std::cin >> x) {
    if (x > best) {
      best = x;
    }
  }
  std::cout << best << "\n";
}
```

**Пример:** ввод `-5 -2 -9` — ожидается `-2`.

**Класс бага:** неверное начальное значение аккумулятора (`best = 0`).
**Где кусается:** поиск min/max, когда данные могут быть все отрицательными или все большими — начинать надо с первого элемента, а не с «удобного» нуля.

## 9.5. День недели 🟡

Программа по номеру дня (1–7) должна печатать `WORKDAY` для 1–5 и `WEEKEND` для 6–7. Но
для `6` она печатает сразу две строки.

```cpp
#include <iostream>

int main() {
  int day;
  std::cin >> day;
  switch (day) {
  case 6:
    std::cout << "WEEKEND\n";
  case 7:
    std::cout << "WEEKEND\n";
  default:
    std::cout << "WORKDAY\n";
  }
}
```

**Пример:** ввод `6` — ожидается ровно одна строка `WEEKEND`.

**Класс бага:** забытый `break` в `switch` — выполнение «проваливается» в следующие `case`.
**Где кусается:** любое меню и разбор кодов на `switch`; провал (fallthrough) иногда нужен намеренно, но здесь он лишний.

## 9.6. Среднее из файла 🔴

Программа читает числа из файла `data.txt` и печатает их среднее. На «ровных» данных
ответ иногда близок к правильному, но систематически занижен — как будто в конце
прибавилось лишнее число `0`.

```cpp
#include <iostream>
#include <fstream>

int main() {
  std::ifstream in("data.txt");
  int x = 0, count = 0;
  long long sum = 0;
  while (!in.eof()) {
    in >> x;
    sum += x;
    ++count;
  }
  std::cout << static_cast<double>(sum) / count << "\n";
}
```

**Пример:** файл с числами `10 20 30 40` — ожидается `25`, а программа печатает `20`.

**Класс бага:** цикл `while (!eof())` делает **лишнюю** итерацию. `eof()` становится истинным только *после* неудачного чтения, поэтому после последнего числа тело выполнится ещё раз с провалившимся `in >> x`.
**Где кусается:** любое чтение файла или потока «до конца». Правильный шаблон — проверять сам факт чтения: `while (in >> x)`.

## 9.7. Печать строки 🔴

Программа должна прочитать строку и напечатать её символы по одному. На обычных строках
всё хорошо, но на **пустой** строке она падает или зацикливается.

```cpp
#include <iostream>
#include <string>

int main() {
  std::string s;
  std::getline(std::cin, s);
  for (size_t i = 0; i <= s.size() - 1; ++i) {
    std::cout << s[i];
  }
  std::cout << "\n";
}
```

**Пример:** пустой ввод (просто `Enter`) — ожидается пустая строка, а программа выходит за границы.

**Класс бага:** беззнаковое переполнение. `s.size()` имеет беззнаковый тип; при пустой строке `s.size() - 1` не становится `-1`, а «оборачивается» в огромное число, и цикл уходит далеко за пределы строки.
**Где кусается:** любое выражение `размер - 1`, `size() - k` над контейнером, который может быть пустым. Надёжнее писать `i < s.size()`.

# Подсказки

> 📖 Мало подсказки? Откройте теорию темы: [раздел справочника](../ref/11-oshibki.md).

<details>
<summary>9.1 — Среднее двух чисел</summary>

- `(a + b) / 2` — это деление **целого на целое**, дробная часть отбрасывается ещё до присваивания в `double`. Для 3 и 4 получается `3`, потом `3.0`.
- Почините делитель: `(a + b) / 2.0`. Тогда деление станет дробным.
</details>

<details>
<summary>9.2 — Ноль или нет</summary>

- В условии стоит `=` (присваивание), а не `==` (сравнение). `x = 0` кладёт в `x` ноль и возвращает `0`, то есть «ложь» — поэтому всегда идёт ветка `else`.
- Замените на `if (x == 0)`. Хороший компилятор с `-Wall` ещё и предупреждает про такое.
</details>

<details>
<summary>9.3 — Сумма массива</summary>

- Во втором цикле условие `i <= n`: при `i == n` обращение `v[n]` выходит **за границу** вектора (индексы идут только `0..n-1`). Отсюда падение или лишнее «мусорное» число.
- Замените на `i < n`. Классическая ошибка «на единицу» (off-by-one).
</details>

<details>
<summary>9.4 — Максимум</summary>

- `best` начинается с `0`. Если все числа отрицательные, ни одно не окажется больше нуля, и напечатается `0` — которого во вводе не было.
- Инициализируйте `best` первым прочитанным числом (а не нулём). Например, прочитайте первое число до цикла либо заведите флаг «первое число ещё не встречалось».
</details>

<details>
<summary>9.5 — День недели</summary>

- В `switch` после `case 6:` нет `break`, поэтому выполнение «проваливается» в следующие `case` — печатаются и `case 7`, и `default`.
- Добавьте `break;` в конце каждой ветки. И подумайте: для 1–5 сюда вообще не попасть отдельным `case`, их ловит `default` — это осознанный выбор или тоже стоит переписать?
</details>

<details>
<summary>9.6 — Среднее из файла</summary>

- Проверка `while (!in.eof())` смотрит на «конец файла» **до** чтения. После последнего числа `eof()` ещё ложь, цикл входит, `in >> x` проваливается, но `sum += x` и `++count` уже выполняются — так `count` становится больше на 1, а среднее занижается.
- Правильно проверять сам факт удачного чтения: `while (in >> x) { sum += x; ++count; }`.
</details>

<details>
<summary>9.7 — Печать строки</summary>

- `s.size()` — беззнаковый тип. Для пустой строки `s.size() - 1` не `-1`, а гигантское число, и `i <= …` держит цикл почти вечно, выходя за границы.
- Пишите условие без вычитания: `for (size_t i = 0; i < s.size(); ++i)`. Или используйте `for (char c : s) std::cout << c;`.
</details>

## Проверьте себя (мини тест-план)

- **9.1:** `3 4` → `3.5`; `2 2` → `2` (проверьте, что дробная часть не мешает целым).
- **9.2:** `0` → `ZERO`; `5` → `NOT ZERO`; убедитесь, что предупреждение компилятора исчезло.
- **9.3:** `N = 1`; убедитесь, что `v[n]` больше не читается.
- **9.4:** все отрицательные (`-5 -2 -9` → `-2`); одно число.
- **9.5:** `6` и `7` → по одной строке `WEEKEND`; `3` → `WORKDAY`.
- **9.6:** файл с `10 20 30 40` → `25` (а не `20`); один элемент; пустой файл (не должно быть деления на ноль).
- **9.7:** пустая строка (пустой вывод, без падения); строка из одного символа; обычная строка.
